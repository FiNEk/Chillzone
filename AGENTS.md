# AGENTS.md

This file provides guidance to AI coding agents (Claude Code and others) when working with code in this repository.

Chillzone — аддон для **WoW: Forever** (клиенты Classic: Lua 5.1), связывающий гильдии, добавленные текущим главой «Чиллзон» в объединение: общий чат на три уровня, перепись гильдий, круги на карте. Состав хранится в `security.union` и подписывается только главой главной гильдии; совпадение названия не даёт членства. Управление в разделе «Объединение» (`UnionPane.lua`) доступно только ему, офицеры гильдий вне объединения видят в нём запрос связи, а передача главы передаёт управление без привязки к имени основателя. Имя главы в `C.MAIN_GUILD_LEADER` — только адрес запроса связи из этого раздела; после смены главы его нужно обновить. Комментарии, документация, строки интерфейса и текст сообщений коммитов — на русском; идентификаторы в коде — английские. Сообщения коммитов — по Conventional Commits (раздел «Коммиты»).

## Команды

**Автономная связь.** `Issuers.lua` хранит отдельные корневые допуски `GRANT` на 366 дней и отзывы (KD); членство по-прежнему не больше 7 дней. `UnionAuthority.lua` закрепляет ключ главы в `security.owner` (UO), переход ключа подписывает прежний владелец. KA с телом `UNIONDECISION` бессрочен, защищён ревизией и поколением; сертификат `leader` сам по себе не даёт управления. Передача главы требует присутствия прежнего владельца ключа, иначе — явный `trust owner-reset` и повторное доверие. Старые клиенты GRANT/UO и новый KA не понимают; для автономной работы обновляются все участники. Подробности и команды отзыва — в `docs/SECURITY.md`.

**Отзыв без корня.** `IssuerRevocations.lua`: глава своей гильдии по свежему ростеру и короткому сертификату автоматически отзывает допуски разжалованных офицеров (KV). Нужен заранее выданный корнем GRANT с назначением `leader`; обычный GRANT `issuer` не даёт права отзыва даже с поддельной ролью главы. KV включает исходный допуск, допуск главы и историческое доказательство его роли, хранится в `security.issuerRevocations` и распространяется через реле и репортёров. Отзыв отменяет и закэшированные дочерние сертификаты, но не более новую выдачу корня. Управление составом объединения это право не даёт.

```bash
luajit tests/run.lua     # все тесты; ненулевой код выхода при падении
bash tests/run-parallel.sh lua5.1 # полный набор в четырёх процессах (Linux или WSL)
luacheck Chillzone tests # линтер, настройки в .luacheckrc
```

На Windows: `scoop install luajit luacheck`; параллельный запуск требует Bash в Linux или WSL. `run-parallel.sh` принимает интерпретатор (по умолчанию `lua5.1`) и число процессов от 1 до 64 (по умолчанию 4), например `bash tests/run-parallel.sh luajit 4`. Он ждёт все части и возвращает ошибку, если хотя бы одна упала; при отмене останавливает дочерние процессы. Обычный `tests/run.lua` остаётся последовательным. Чтобы прогнать не всё, задайте `CZ_TEST_FILTER=<часть имени теста>` (сравнивается подстрока имени из `T.test`); `CZ_TEST_PROGRESS=1` печатает каждый пройденный тест. `CZ_SEED=<n>` меняет seed симулятора в `test_relay` и `test_chat`. CI (`.github/workflows/ci.yml`) запускает линтер, проверку оболочки и полный набор в четырёх процессах отдельно для Lua 5.1 и LuaJIT на каждый PR и пуш в `main`; PR, где меняются только `## Version` и `C.VERSION`, набор не гоняет и лишь сверяет две записи версии.

Сборки нет: игра грузит папку `Chillzone/` как есть. `main` защищена: любые изменения, включая повышение версии, проходят через PR с успешными `Luacheck`, `Tests (lua5.1)` и `Tests (luajit)`. Версия записана в **двух** местах: `## Version` в `Chillzone/Chillzone.toc` и `C.VERSION` в `Chillzone/Config.lua`. Тест следит, чтобы они совпадали. Помощники репортёра (ответ на Q1, прямой запрос отчёта) работают только у клиентов новее `C.LAST_WITHOUT_HELPERS` — последней вышедшей версии без них; если релиз выходит без помощников, эту постоянную нужно поднять до его номера. Для релиза сначала слить PR с версией, подтянуть `main` и только затем поставить и отправить тег `vX.Y.Z`. Перед повышением версии набор локально не гонять, если CI на `main` зелёный. Workflow `release.yml` дожидается CI того же коммита на `main` (своих проверок не гоняет, если тот прогон есть и не отменён), сверяет тег с версией, собирает `Chillzone-X.Y.Z.zip` и создаёт черновик релиза (либо прикладывает архив к существующему). Публиковать после успешного workflow, проверки архива и заполнения описания. После публикации пользователем `curseforge.yml` загружает тот же архив на CurseForge; для релизов, опубликованных через `GITHUB_TOKEN`, нужен ручной запуск. Подробный порядок и настройка — в [docs/DETAILS.md](docs/DETAILS.md#выпуск-версии).

## Коммиты

Сообщения коммитов — по [Conventional Commits 1.0.0](https://www.conventionalcommits.org/ru/v1.0.0/): `<тип>(<область>): <описание>`. Тип и область — английские, строчными. Описание — по-русски, со строчной буквы, без точки в конце: что сделано. Тело и сноски тоже по-русски, ключевые слова сносок (`BREAKING CHANGE`, `Co-Authored-By`) — как в спецификации.

- Типы: `feat` — новое для игрока или офицера; `fix` — исправление; `perf` — производительность; `refactor` — переделка без изменения поведения; `test` — только тесты и симулятор; `docs` — только документация; `ci` — workflow в `.github/` и скрипты запуска тестов; `chore` — прочее, в том числе версия; `revert` — откат.
- Область необязательна: модуль или раздел строчными без `.lua` — `relay`, `census`, `chat`, `groups`, `crafters`, `security`, `ui`, `release`. Префикс `Chillzone:` больше не пишется.
- Изменение формата обмена (см. «Совместимость») отмечается `!` перед двоеточием и сноской `BREAKING CHANGE: <что перестанет работать у старых версий>`.
- Повышение версии — `chore(release): версия X.Y.Z`.
- Заголовок PR пишется так же, как сообщение коммита.

```text
feat(crafters): витрина до размещения карточки
fix(relay): пауза полосы WHISPER после отказа сервера
feat(codec)!: новое поле в отчёте переписи
```

Старые коммиты в стиле `Chillzone: что сделано` не переписываются.

## Устройство

**Загрузка.** Порядок файлов в `Chillzone.toc` — это порядок загрузки. Каждый файл начинается с `local ADDON, ns = ...` и кладёт свой модуль в общую таблицу (`ns.Util`, `ns.Config`, `ns.Codec`, `ns.Comm`, …). Новый файл нужно вписать в toc: тесты грузят аддон по нему. В глобальное окружение аддон пишет только `ChillzoneDB` (SavedVariables), `SLASH_CHILLZONE*` и `SlashCmdList`. Симулятор ловит утечки (`Client:Leaks`), а luacheck не пропускает запись в другие глобалы.

**Ядро (`Core.lua`).** Внутренняя шина `ns.On`/`ns.Fire` (например, событие `CHAT` для окна) и события игры через `ns.RegisterEvent`. Таймеры — `ns.After`/`ns.Every`, подкоманды — `ns.Command`, их разбор — `ns.RunCommand`, строки для `/chillzone status` — `ns.Status`. `/chillzone` принимает только команды. `/cz`, `/чз` и `/чиллзон` по Enter выполняют известную команду, остальной текст отправляют в общий чат. `/cz1`–`/cz3` и `/чз1`–`/чз3` отправляют любой текст в соответствующий канал. Пустая команда по Enter открывает окно нужного канала без подсказки в чате. Набор текста и пробел после команды окно не открывают. Ошибки перехватывает `ns.SafeCall`, их видно в разделе «Отладка». Время для сравнения между клиентами — `ns.ServerTime()`, локальное — `ns.Now()`.

**Слои.**
- Чистые модули без вызовов игры при загрузке: `Util.lua` (регистр кириллицы — `string.lower` в игре трогает только ASCII; правило «своей» гильдии; имена Forever) и `Codec.lua` (формат всех сообщений, описан в шапке файла). Их тестировать проще всего.
- Транспорт `Comm.lua`: очередь отправки, нарезка на куски по 255 байт и сборка, разбор входящих по типу (`ns.Comm.On("Q1", fn)`). Очередь общая (приоритеты, ключи, `before`), но GUILD и WHISPER — две полосы со своей квотой за такт, своей паузой после отказа сервера (коды 3/8/9) и своим сбросом давних заданий (`HOLD_MAX`): сервер Forever ограничивает GUILD (около 10 сразу, затем 1 в секунду), и поток GUILD не должен задерживать шёпоты. Блокировка чата держит обе полосы. Порядок между полосами задаёт только `before`: задание с ключом K не уходит, пока не завершено поставленное с `before = K` (KT по GUILD перед KP шёпотом в `Security.lua`); остальные задания его полосы не ждут.
- Логика: `Census` (приветствия H1, выбор репортёра, отчёты, очередь помощников репортёра `Census.Helpers` и их ответ на Q1), `Roster` (свой ростер → отчёт), `Data` (хранилище отчётов, ранги чужих гильдий, сводки), `Relay` (ретрансляторы), `Channel` (канал игры `ChillzoneChatA`/`ChillzoneChatH` для строк `/cz1`: вход, отправка обычным текстом, бюджет сервера 3 строки за ~30 с по эху своих строк, состояние канала — сломан до перезахода без эха; отказ при входе (`NOT_ALLOWED_IN_CHANNEL`, бан, пароль) — «не пускает»: после отказа игра держит канал выключенным и до перезахода вход не отправляет, поэтому снова вход — только при следующем входе персонажа; `INVALID_NAME` (ответ на команду канала с непринятым именем) теряет канал — сломан до перезахода; `ADDON_ACTION_BLOCKED` выключает отправку до `/reload`; страж по образцу Olympus, но с отличиями (их список — в шапке раздела в `Channel.lua`) — после входа в канал и после `/reload` спрашивает владельца (`DisplayChannelOwner`: создателю канала Forever о месте не сообщает), пока клиент владелец или модератор канала, снимает чужой пароль (только владелец) и увиденные баны участников объединения, не посторонних (список в `ns.store.channelGuard` с названием канала), а «стук» `Channel.Knock` снимает бан с автора подписанной строки `/cz1` без копии из канала; если игра не пускает вызовы стража из таймера, они идут из нажатия клавиши (`Channel.Pressed` в `Chat.Send`); фильтр сырых строк, уведомления в журнал), `Online` (поимённый онлайн чужих гильдий: запрос OQ и страницы OL прямым WHISPER, только пока список на экране — в «Переписи» или «Мастерах профессий»), `Pull` (устаревший чужой отчёт: запрос RQ его автору и ответ RA прямым WHISPER в обход реле; спрашивает репортёр, а через `Config.PULL_HELPER_DELAY` и первый помощник), `Security` (ключи, сертификаты, корни доверия, подписанные пакеты S1; см. `docs/SECURITY.md`), `TrustCatalog` (каталог доверия своей гильдии — KT, UO, KA, KD, KV — по GUILD один раз на всех офицеров: копия засчитывается по `Comm.Watch` — своя отправка или те же байты от офицера, окно `TRUST_SHARE_WINDOW`, свой порядок офицеров у каждой записи, перед отправкой — `opts.skip` в `Comm.Send`; новые записи и явные действия — `TrustCatalog.Direct`, сразу), `Chat` (общий чат; гильдия автора строки из канала по имени — `Chat.Attribute`, сведение копий из канала и подписанных), `GuildChat` (чат своей гильдии из событий игры), `Zones` (зона → `m<uiMapID>`), `Update` (версии новее своей из H1 и последнего поля R1; два игрока — предупреждение об устаревшем аддоне).
- Состояние операций: `Activity` (учёт без обращений к игре: операции `Start`/`Touch`/`Finish` и пробы `Probe`, их строку внизу окна готовит `Views.Activity`) и `Refresh` (кнопка «Обновить» и `/chillzone refresh`: ростер, затем Q1 или отчёт репортёра, опрос реле и JQ). Новое ожидание, которое видит игрок, оформляется операцией или пробой; фон (приветы, плановые чтения, аренды) туда не попадает.
- Вступление: `Who` (штатный `/who`, диапазоны уровней при лимите 50 строк), `Recruit` (прямые WHISPER J1/J2/J3, заявки и явный текст письма JT), `RecruitSync` (общая очередь офицеров: запрос JQ по GUILD, заявки JS и решения JX адресно по WHISPER), `RecruitPane` (экран новичка, собственное окно письма, отдельная вкладка «Заявки», число заявок — в подсказке). Контакты из подсказки сверяются с локальным `/who`; заявка не даёт доступа к подписанной сети. Общая очередь и вкладка «Заявки» доступны только офицерам по свежему ростеру; входящие рядового уходят офицерам, своей вкладки у него нет. Текст для общей очереди берётся только из JT, не из обычных шёпотов. Приглашает сам офицер командой `/ginvite` из поля `CommandBox` (кнопка — при игровом праве `CanGuildInvite`); заявка закрывается, когда новичок вступил. Стандартные popup для письма не используем из-за taint на Forever.
- Поиск групп: `Groups` (доска объявлений объединения: подписанный `G1` идёт как строка чата — по GUILD своей гильдии и через реле в режиме `P`; через реле ещё и второй подписью в конверте строки чата `M1~A~гильдия~G1~...` (`Codec.WrapGroup`): его пересылают и реле 0.13.1 и старше, а их чат его отбрасывает; `Comm.Dispatch` разворачивает конверт обратно в G1 с `ctx.wrapped`, конверт правок — не чаще `C.GROUPS_WRAP_GAP`; вошедший спрашивает объявления запросом GQ по GUILD, отвечают авторы своей гильдии и репортёр; заявка GA, отзыв GW и ответ GR — прямым WHISPER без подписи, членство заявителя проверяется по сертификату; своё объявление и заявки хранятся в `ns.char.groups` и переживают `/reload`) и `GroupsPane` (вкладка «Группы»). Название объявления — свободный текст: списка мест в аддоне нет, а список занятий игры (`C_LFGList`, может отсутствовать) только подставляет название в поле. Роли игрок отмечает сам, игра их не сообщает. Имена участников группы не рассылаются. Приглашение в группу — только из щелчка. Сроки и лимиты — `C.GROUPS_*`; порядок пакетов одного автора и защита от повтора старого — по времени и номеру подписи.
- Мастера профессий: `Crafters` (каталог ремесленников объединения: свои профессии читаются из открытого окна профессии через `C_TradeSkillUI`, чужое окно и бой пропускаются; подписанная карточка `W1` ходит только в конверте строки чата `M1~A~гильдия~W1~...` (`Codec.WrapCraft`) по GUILD своей гильдии и через реле в режиме `P`, `Comm.Dispatch` разворачивает её в W1 с `ctx.wrapped`; реле и чат 0.14.2 и старше её пересылают и молча отбрасывают; автор повторяет карточку раз в `Every()` минут, время отправки хранится в `ns.char.crafts` и переживает `/reload`; порядок пакетов — по времени и номеру подписи; список рецептов — запрос `WR` и страницы `WL` прямым WHISPER без подписи, как OQ/OL, со сверкой по хешу; по сети идут только номера рецептов, названия каждый клиент берёт у игры порциями, значки и реагенты — только для видимых строк списка; «в игре» — по ростеру и спискам `Online` (`Crafters.Presence`); рецепты персональных при поднятии предметов скрыты по умолчанию — тип привязки из `GetItemInfo`, настройка `ns.db.settings.craftBound`; фильтр «Уровень от — до», как на аукционе, — требуемый уровень предмета оттуда же, только по загруженным спискам; витрина — до `C.CRAFT_SHOW` своих рецептов в самой карточке W1 (номера после хеша профессии), отмечается звёздочками в своей карточке (кнопка «Витрина» открывает её и до размещения — черновик `Crafters.Own(true)`) и хранится в `ns.char.crafts.show`, видна значками в строке каталога, первой в карточке и в поиске без загрузки списка) и `CraftersPane` (вкладка «Мастера профессий»). Сроки и лимиты — `C.CRAFT_*`.
- Кадры: `Transfer` (просьбы офицерам гильдии исключить или пригласить игрока, перенос — два шага; TQ, TA и TC прямым WHISPER без реле; аддон не исключает и не приглашает вовсе — Forever запрещает это и аддону, и макросу, — а показывает команду `/gremove` или `/ginvite` в своей строке (`CommandBox.lua`, она же в «Заявках»; строка ведёт и очередь команд — следующая только по итогу текущей, без таймеров), её вводит сам игрок; просить о чужой гильдии могут владелец и офицеры главной, пригласить своего игрока в другую гильдию — офицер с подтверждённой ролью; «сделано» — по системной строке гильдии (`Roster.GuildEvent`, событие `GUILD_MEMBER`) или по ростеру получателя, при неполном ростере (`Roster.complete`) — только по строке; всё в памяти до `/reload`) `TransferPane` (раздел «Кадры» в «Управлении»: форма и просьбы) и `RosterPane` (раздел «Состав»: состав своей гильдии с давностью входа, команда исключения по щелчку по строке и очередь «Исключать по очереди» для не заходивших дольше N дней). Права и проверки — в `docs/SECURITY.md` («Кадры»).
- Отрисовка: `Views.lua` готовит строки и данные, а рисуют их `UI.lua` (окно и вкладки: сверху повседневные значки, ниже с отступом служебные — Настройки и «Управление»; «Управление» переключает разделы «Объединение», «Состав», «Кадры», «Отладка» и «Журнал», а их ключи остаются страницами для `UI.Toggle`, `UI.Current` и команд; без «Объединения», «Кадров» и «Отладки» значка нет, журнал открывает кнопка в Настройках), `ChatPane.lua`, `CensusPane.lua`, `GroupsPane.lua`, `CraftersPane.lua`, `TransferPane.lua`, `RosterPane.lua` и `Debug.lua`. Размер окна игрок меняет уголком справа внизу: не меньше исходного 814×426, под которое свёрстаны вкладки, и не больше экрана; размер хранится в `ns.db.settings.frame` (`w`, `h`) рядом с местом. Новую вставку `UI.InsetSize()` (у исходного окна 804×340) получает `Layout(ширина, высота)` каждой вкладки из списка `LAYOUTS` в `UI.lua`: лишнюю ширину отдают спискам и колонкам, правые панели «Групп» и «Мастеров» остаются прежней ширины у правого края, лишнюю высоту — числу строк таблиц и списков. Пока игрок тянет, каждый кадр зовётся `Layout(ширина, высота, true)` только у открытой вкладки: он перекладывает готовое без нового сбора и сортировки (у «Переписи» таблица людей ждёт отпускания), а по отпусканию — `Layout` всех вкладок и `UI.Render`. Окно держится одной точкой `TOPLEFT` и явным размером, кэш расположения игры (`SetUserPlaced`) выключен; размер, сменившийся без уголка, аддон возвращает и пишет в журнал. Новой вкладке с постоянными размерами нужен свой `Layout` в этом списке. Круги на карте мира — `Map.lua` через HereBeDragons-Pins.

**Главное ограничение платформы.** На Forever аддон-сообщения в пользовательском канале не доставляются, доставляются только GUILD и WHISPER. Поэтому между гильдиями всё идёт шёпотом через реле: автор → реле (`RL`) → репортёр каждой гильдии (`RM`) → его гильдия по GUILD (`RG`). Отчёт переписи автор шлёт сразу двум отвечающим реле из тройки (`Relay.Out`), строку чата — одному. В каждой гильдии все клиенты одинаково и детерминированно выбирают одного репортёра. Строки чата гильдия берёт по RG только от него. Отчёт переписи новее сохранённого принимается от любого согильдийца, а реле главной гильдии отдаёт чужой отчёт своей гильдии само (`Relay.Forward` и обработчик RG в `Relay.lua`, лимит `Config.RG_SIDE_PER_MIN`). На Q1 первым отвечает репортёр, а недостающие отчёты досылают по общей очереди помощники (`Census.Helpers`, `Config.Q1_HELPERS`); показанным считается только пакет, совпавший байт в байт и услышанный в пределах лимита отправителя. Отчёт другой гильдии старше `Config.PULL_AFTER` гильдия берёт у его автора напрямую (`Pull.lua`: `RQ` и `RA` шёпотом; отвечает любой обновлённый участник той гильдии своим отчётом репортёра или отчётом, подписанным ради ответа по своему ростеру, который не уходит ни через реле, ни своей гильдии; проверка как от реле через `Relay.Direct`). Строка чата уходит двумя путями: `M1` по GUILD своей гильдии и через реле остальным. Дубли отбрасывает `Chat.Receive`. Обычный текст в пользовательском канале доходит, но только из нажатия клавиши: поэтому строка `/cz1` ещё и уходит обычным текстом в канал игры синхронно из `Chat.Send`, до подписи (не из таймера и не в блокировке, `Config.CHANNEL_CHAT`). Строки канала не подписаны и прав не дают; гильдию автора получатель угадывает по имени, иначе показывает `<?>`. Копию из канала и подписанную сводят `Chat.ReceivePlain` и `Chat.Receive` по автору и тексту с учётом маски фильтра брани (`U.MaskMatch`): фильтр игры меняет текст строки канала прямо в событии. `/cz2` и `/cz3` идут только через реле. Шептать нужно на «Имя Фамилия» без реалма. Свою гильдию клиент видит только по своему ростеру. Доверие к репортёрам и реле задаёт `Config.TRUST_ANY_MEMBER` (сейчас `true`, любой участник). Подробная схема, роли реле и известные дыры — в `docs/DETAILS.md` («Как это работает», «Ограничения»).

**Совместимость.** Изменение формата в `Codec.lua` или сообщений `Security.lua` (S1, K*) ломает обмен со старыми версиями у игроков. Если формат меняется, это нужно явно отметить в коммите (`!` и `BREAKING CHANGE`, см. «Коммиты»), в PR и в описании релиза.

**Диагностика.** `Diagnostics.lua` наблюдает за исходящими WHISPER через безопасные пост-хуки API: сохраняет адресата, префикс, API и доступный стек вызова, но не читает текст сообщения или пакета. Наши отправки записываются до API, чтобы поймать синхронный отказ. `JournalPane.lua` — раздел «Журнал» для любого игрока, включая персонажа без гильдии: запись, просмотр, очистка и копирование полного отчёта через своё поле. `/chillzone debug` переключает запись и открывает журнал, `/chillzone journal` и `/chillzone log [N]` открывают его без вывода в обычный чат. Новые ошибки содержат время и версию; прежние при экспорте явно помечаются. Раздел «Отладка» со сводкой реле по-прежнему только для глав и офицеров. `Perf.lua` — замер производительности по запросу (`/chillzone perf` или кнопка в «Журнале»): на время записи подменяет `ns.SafeCall`, считает по меткам своё время и выделенную память и запоминает длинные кадры, результат входит в отчёт журнала. Новый постоянный `OnUpdate` нужно обернуть в `ns.Perf.Wrap`, иначе замер его не увидит. Как читать отчёт — в `docs/DETAILS.md` («Замер производительности»). `Net.lua` — счётчики сети, ведутся всегда: куски и сообщения по полосам и типам (`Net.Label`: конверт реле и вложенный тип без `S1`), пик за скользящую минуту с составом, отказы сервера, выброшенные задания, ожидание в очереди и отправители GUILD. `Comm` сообщает о каждом событии очереди и приёма; сессия хранится в `ns.db.net`, переживает `/reload` и входит в отчёт журнала разделом «Сеть». Как читать — в `docs/DETAILS.md` («Счётчики сети»).

## Правила, которые проверяют тесты и игра

- Только Lua 5.1: без `goto` и меток. UTF-8 без BOM. Файл начинается с комментария или с `local ADDON, ns = ...` (`tests/test_static.lua`).
- В строках, которые видит игрок, допустимы только ASCII, кириллица и символы `«`, `»`, `—`, `№`. Остального (`·`, `…`, `–`, `→`, `×`) в шрифте игры нет, вместо них рисуются квадраты. Тест проверяет все строковые литералы в коде аддона, в комментариях можно что угодно. Тексты интерфейса лежат в `Locale.lua` (`L.KEY`).
- Режим наложения — только через `SetBlendMode`. Второй аргумент `SetNormalTexture`/`SetCheckedTexture`/… игра молча теряет.
- Taint: `ChatPane.lua` не трогает поле ввода и окна чата игры. Список запретов — в шапке файла. Исключение — `ChatPane.Whisper`: кнопки «Шёпот» и «Шепнуть» открывают поле чата игры через `ChatFrameUtil.SendTell` (на старых клиентах `ChatFrame_SendTell`), как Olympus с мышью и клавиатурой; в режиме геймпада и без API — поле окна Chillzone. Щелчок по имени в чате окна по-прежнему ставит шёпот в поле окна. `Chat.lua` не перехватывает ввод игрового поля, не пишет его текст, атрибуты и методы и не переводит фокус при наборе `/cz`. Если нарушить эти границы, игра может заблокировать следующий `/cast` или `/target` игрока; после изменения работы с игровым вводом нужна проверка в игре. `ChatFrameUtil.SetChatFocusOverride` не используем: он забирает любой `OpenChat` без вкладки, включая шёпот Battle.net и ответы. Настройка копий управляет только выводом, а Enter перехватывается привязкой лишь для окна Chillzone и поля вкладки «Чиллзон».
- `GuildInvite`, `GuildUninvite` и `C_GuildInfo.Invite`/`Uninvite` на Forever заблокированы и для аддона, и для макроса: не вызываем, показываем команду в `CommandBox`. Симулятор записывает такие вызовы в `c.forbidden`, а набранную игроком команду изображает `Client:GuildCommand`.
- Новый вызов API игры нужно добавить в `read_globals` в `.luacheckrc`, а если код выполняется в тестах — ещё и заглушку в `Env` в `tests/wow.lua`.
- `Chillzone/libs/` — сторонние библиотеки (LibStub, CallbackHandler, HereBeDragons). Их не правим и не линтим.
- `Chillzone/media/` — свои текстуры: несжатые 32-битные TGA с прозрачностью, стороны — степени двойки. `icon.tga` — круглый значок (миникарта, портрет окна), `logo.tga` — логотип целиком (`## IconTexture` в toc). Тест проверяет, что пути из toc и кода ведут на такие файлы.

## Тесты

`tests/lib.lua` — маленький каркас: `T.test`, `T.eq`/`T.ok`/`T.no`/`T.same`, а `T.load(files, env, ns)` грузит файлы аддона в отдельное окружение через `setfenv`. Скомпилированные функции кэшируются по полному пути в пределах процесса; каждый вызов выполняет файл заново со своими `env` и `ns`. После изменения исходников нужен новый запуск тестов. Новый набор тестов нужно вписать в `SUITES` в `tests/run.lua`.

`CZ_TEST_SHARD_INDEX` и `CZ_TEST_SHARD_COUNT` задаются только парой: номер части от 1 до числа частей. Тесты распределяются по индексу регистрации, до применения фильтра, поэтому части не пересекаются и вместе покрывают полный набор. `tests/test_runner.lua` проверяет разбиение, фильтр и ошибки; `bash tests/test_parallel_runner.sh` — запуск процессов, пути с пробелами, отказ одной части и отмену.

`tests/wow.lua` — симулятор мира. В нём несколько клиентов, у каждого своё окружение и своя копия аддона. Есть гильдии с ростерами, доставка GUILD и WHISPER, общие часы и таймеры. Основное API: `World:Guild`, `World:Client{...}`, `World:Run(seconds)` (двигает часы и запускает таймеры), `Client:Fire`, `Client:Slash`, `Client:Saw(text)`. Так проверяются сценарии переписи, реле и чата целиком.

То, чего тесты не видят (окно, карта, миникарта), нужно проверить в игре по чек-листу из `docs/DETAILS.md` («Проверка в игре»).
