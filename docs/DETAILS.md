# Chillzone — подробно

Аддон для **WoW: Forever**. Он связывает главную гильдию «Чиллзон» и гильдии, которые её глава добавил в объединение (название может быть любым):

- **Перепись.** Численность гильдий, сколько участников в игре, главы, офицеры, классы, уровни, неактивные.
- **Королевство.** Глава главной гильдии «Чиллзон» — Король. Главы остальных гильдий — Лорды, офицеры — Капитаны.
- **Карта.** Круги на карте мира показывают, сколько участников в каждой зоне. Зоны видны только у гильдий, чей репортёр согласился ими делиться.
- **Общий чат** с тремя уровнями:

| Команда | Канал | Кто может писать и читать |
|---|---|---|
| `/cz1` | «Чиллзон» | все участники |
| `/cz2` | «Офицеры» | главы и офицеры гильдий |
| `/cz3` | «Главы» | главы гильдий и офицеры главной гильдии |

Офицер — тот, чьё звание отмечено в настройках гильдии галочкой «Офицер» (как в ChillZoneUnion 0.6). Номер звания, его название и право приглашать роли не решают. Если игра не отдала права званий, офицерский доступ не предоставляется. Глава определяется рангом 0.

- **Окно чата** в стиле «Гильдии и сообществ». Слева — каналы: свои гильдия и офицеры плюс три общих. В центре — сообщения и поле ввода, справа — люди. Перепись, королевство и настройки — вкладки на правом краю того же окна.

Код частично портирован из [Olympus](https://github.com/dnl-gentile/olympus-addon) (MIT), подробности — в [THIRD_PARTY.md](../THIRD_PARTY.md).

## Установка

1. Скопируйте папку `Chillzone` в `World of Warcraft\_classic_era_\Interface\AddOns\` (или в папку AddOns вашего клиента Forever).
2. Перезапустите игру и включите аддон в списке.
3. Проверьте: `/chillzone status`.

## Команды

| Команда | Что делает |
|---|---|
| `/chillzone` | открыть или закрыть окно (по умолчанию — чат) |
| `/chillzone census`, `/chillzone kingdom`, `/chillzone settings` | окно на нужной вкладке |
| `/cz1 текст`, `/cz2 текст`, `/cz3 текст` | написать в общий чат |
| `/cz команда` | выполнить известную команду аддона, например `status`, `settings`, `trust init` |
| `/cz текст` | отправить в общий чат, если первое слово не является командой; любой текст — через `/cz1` |
| `/cz`, `/cz1`, `/cz2`, `/cz3` без текста | по Enter открыть окно нужного канала, без подсказки в чате |
| `/чз`, `/чз1`, `/чз2`, `/чз3`, `/чиллзон` | то же на кириллице: `/чз` = `/cz`, `/чз1` = `/cz1`, `/чиллзон` = `/cz` |
| `/chillzone zones on\|off` | делиться зонами своей гильдии (по умолчанию включено; при обновлении включается один раз, отказ после этого сохраняется) |
| `/chillzone map on\|off` | круги на карте мира |
| `/chillzone chat on\|off` | показывать общий чат |
| `/chillzone window <вкладка>` | выводить общий чат во вкладку чата игры с таким названием (пусто — основное окно); то же выбирается в настройках |
| `/chillzone ignore Имя Фамилия` | игнор в общем чате (повтор снимает) |
| `/chillzone history 1\|2\|3` | последние 20 строк канала |
| `/chillzone relay` | список ретрансляторов и их состояние |
| `/chillzone trust init` | офицер задаёт корень доверия своей гильдии; один раз на гильдию |
| `/chillzone trust` | известные корни доверия |
| `/chillzone link Имя Фамилия`, `/chillzone accept Имя Фамилия` | запросить и подтвердить первое соединение гильдий |
| `/chillzone trust reset Название гильдии` | отозвать доверие после утраты или компрометации ключа |
| `/chillzone relay ping` | проверить ретрансляторы заново |
| `/chillzone refresh` | обновить данные сейчас: ростер, отчёты гильдий, реле и заявки (то же, что кнопка «Обновить» в окне), не чаще раза в 30 секунд |
| `/chillzone minimap` | спрятать или показать кнопку у миникарты |
| `/chillzone status` | кто я, гильдия, репортёр, реле, канал, счётчики, версия аддона |
| `/chillzone diag` | окно на вкладке «Отладка» (главы и офицеры) |
| `/chillzone journal`, `/chillzone log [N]` | отдельная вкладка «Журнал», доступна любому игроку |
| `/chillzone debug` | включить или выключить запись диагностики и открыть «Журнал» |
| `/chillzone perf` | начать или остановить замер производительности и открыть «Журнал» |
| `/chillzone requests` | отдельная вкладка «Заявки» (главы и офицеры) |

`/cz`, `/чз` и `/чиллзон` по Enter сначала проверяют первое слово по списку команд аддона: `/cz settings`, `/чз status` и `/cz trust init` выполняют команды. Остальной текст отправляется в общий чат. Для сообщения со словом команды в начале используйте `/cz1`, например `/cz1 status`. `/chillzone` принимает только команды. Набор текста и пробел после алиаса не открывают окно Chillzone и не переводят в него фокус.

## Заявки на вступление

У персонажа вне гильдий Чиллзона `/chillzone` открывает экран вступления. Если персонаж состоит в гильдии вне объединения, вступление называет эту гильдию и объясняет, что подключает её глава «Чиллзон» по запросу её офицера (`/chillzone link`). Поиск через штатный `/who` находит участников своей фракции и группы реалмов, группирует их по гильдиям. Один запрос — из одного щелчка, не чаще раза в 10 секунд. Если сервер вернул 50 строк, следующие щелчки проверяют диапазоны уровней и объединяют результаты без дублей. Через 15 минут поиск начинается заново. После тайм-аута или отмены поиска чужим `/who` выдерживается ещё 30 секунд на запоздалый ответ. Открывается обычный список `/who`: аддон не меняет обработчики и события окон игры.

После поиска J1 (запрос подсказки маршрута) получают до трёх найденных участников за раз, не чаще раза в 15 секунд; если пауза ещё не прошла, пачка уходит сразу после неё, без нового щелчка. Сначала по одному из гильдий, чьих офицеров ещё не знаем (гильдии с местами — первыми), затем ещё участники тех же гильдий; одного участника повторно спрашиваем не раньше чем через 10 минут. Участникам гильдии, заполненной по подсказке, J1 больше не уходит. J2 возвращает флаг «не беспокоить», число свободных мест и до двух контактов на гильдию — главу и офицеров в игре. Своя гильдия берётся из ростера; чужие — из свежей подписанной переписи без конфликта, а руководство чужой гильдии дополнительно сверяется с сертификатами. Заполненная гильдия (мест 0) тоже попадает в ответ, после гильдий с местами; в 0.6.0 она пропускалась вместе с офицерами. Ответы разных участников складываются (до шести офицеров на гильдию), места берутся из последнего ответа. Отправленные J1 и полученные J2 пишутся в лог аддона.

Просьба уходит только главе или офицеру: под названием гильдии видны офицеры, которых назвала подсказка и `/who` нашёл в этой гильдии. Гильдии с местами стоят в списке первыми, затем гильдии без подсказки, заполненные — внизу. Гильдия с местами из J2 видна в списке сразу, даже если `/who` не нашёл ни одного её участника; до проверки офицера её кнопка неактивна.

В заполненную гильдию (подсказка назвала 0 мест) просьба не уходит: её офицеры видны, но кнопка «Мест нет» неактивна, а офицеров по имени не проверяем. Неизвестное число мест нулём не считается. Если новый J2 сообщил 0 мест, пока открыто письмо, оно закрывается, а пакеты просьбы, ещё ждущие в очереди, не отправляются. Когда следующий ответ сообщает о свободных местах, писать снова можно. В 0.7.1 офицерам заполненной гильдии писать было можно.

Большая заполненная главная гильдия занимает все 50 строк общего запроса `g-"Чиллзон"`, и гильдии поменьше в него не попадают. Поэтому после первой подсказки щелчок «Найти гильдии» выбирает запрос по ней (`Recruit.NextSearch`), а строка под кнопкой говорит, что он сделает. По гильдиям с местами, начиная с тех, где мест больше, и даже если `/who` их ещё не находил:
- если подсказка назвала офицера, а `/who` его не нашёл (в большой гильдии офицера может не оказаться среди 50 строк), — проверка одного офицера запросом `/who "Имя Фамилия"` (вариант `n-"Имя Фамилия"` на Forever ничего не находит; ранга `/who` не показывает, его назвал J2), одно имя — раз за раунд;
- иначе — поиск этой гильдии по названию из подсказки `g-"Название"`, раз за раунд. Его не делаем, если гильдия уже нашлась целиком: запросом без диапазона уровней, который сервер не обрезал до 50 строк. Найденные участники получают J1, и их ответ называет офицеров.

Запрос, на который не пришёл ответ (тайм-аут или чужой `/who`), не засчитывается, и следующий щелчок его повторит. Гильдия, где новичку уже есть кому написать, пропускается. Когда для гильдий с местами делать нечего, поиск идёт дальше по диапазонам уровней, известным гильдиям объединения и названиям из подсказок J2. Рядовой участник адресатом не бывает, даже если офицеров не видно: тогда кнопка неактивна, а строка гильдии говорит, что офицеры пока не известны. Ранг чужой гильдии новичку больше узнать неоткуда, поэтому офицеров видно, только если в игре есть участник гильдии с аддоном: 0.6.0 называет офицеров только гильдий со свободными местами, офицеров заполненной гильдии — версия новее; после 0.7.1 писать им новичку не предлагается. Король контактом не предлагается.

Нажатие «Попросить приглашение» открывает собственное окно аддона с редактируемым текстом и ещё раз запрашивает настройки адресата. Ответ «не беспокоить» или «мест 0» закрывает уже открытое письмо. Отправка — один обычный шёпот, прежний J3 с гильдией, уровнем и классом и дополнительный JT с явным текстом той же просьбы тому же игроку. Для обоих аддон-пакетов проверяется место в очереди до отправки шёпота. Между просьбами — 20 секунд; повторно тому же адресату в этой сессии не пишем. Ответы выделены на экране вступления. Старый получатель понимает прежний J3 и игнорирует JT.

Входящие находятся на отдельной вкладке «Заявки». Это значок без подписи, как остальные вкладки; число заявок показывает подсказка при наведении. Вкладку видят только главы и офицеры по свежему ростеру (`RecruitSync.IsOfficer`), пустую тоже. Открыть её можно через `/chillzone requests`; рядовому команда отвечает, что вкладка только для глав и офицеров. Звание проверяется при каждом обновлении ростера: после понижения вкладка пропадает и окно переключается на чат. Офицеры получают общую очередь своей гильдии. У рядового вкладки нет: заявка, полученная им, передаётся офицерам автоматически, а в чат выводится, что её увидят глава и офицеры. В строке указано, кто получил просьбу первоначально.

Право «Пригласить» определяется `CanGuildInvite`, отдельно от офицерского доступа к общему чату. Приглашение — только из щелчка штатным `C_GuildInfo.Invite` или `GuildInvite`. Офицер может обработать заявку, адресованную другому участнику. «Отклонить» отправляет один шёпот от имени обрабатывающего игрока. Приём, отказ и «Закрыть для всех» передают решение остальным офицерам и первоначальному адресату; после доставки решения их старые кнопки не действуют. Офицеру без права приглашать вместо приёма и отказа доступна «Направить к офицеру»: новичку уходит контакт другого офицера в игре. Перед действием ещё раз проверяются сама заявка, гильдия, свежий ростер и членство новичка.

Количество заявок и время до их обработки не ограничены, весь список доступен с прокруткой. Новые заявки не вытесняют старые, а возраст заявки сам по себе не отменяет её. Заявки уже вступивших игроков удаляются при обновлении ростера. Повтор от одного из 128 последних отправителей отклоняется в течение 10 минут; уведомления в чат — не больше 6 за минуту. Выход, `/reload` и смена гильдии очищают локальную память; офицер может восстановить очередь у оставшихся участников. После выхода всех держателей она теряется. Настройка «Принимать обращения о вступлении» и `/chillzone nocontact on|off` сохраняются для аккаунта, как в Olympus, и относятся к личным обращениям, а не к общему списку офицера.

`RecruitSync.lua` передаёт JQ по GUILD для запроса снимка, JS по WHISPER — заявку с первоначальным адресатом, идентификатором, временем создания и редакцией текста, JX по WHISPER — решение офицера. Снимок запрашивается при входе, повышении до офицера, открытии вкладки и периодически раз в две минуты; «Обновить» запрашивает его вручную, не чаще раза в 30 секунд. Новый офицер также получает очередь, когда другие участники увидели его в ростере. Большие снимки отправляются постепенно, не переполняя очередь Comm. Закрытия хранятся в памяти и подавляют старые снимки; более новое обращение того же новичка остаётся допустимым. Перед отправкой ещё раз проверяются гильдия и права адресата. Потеря офицерского звания убирает чужие заявки. Общий список не использует реле и не выдаёт сертификатов. Текст в JS берётся только из явного JT, даже если обычный шёпот пришёл раньше J3: предыдущая личная беседа и следующие реплики не пересылаются. Если новичок использует старую версию без JT, очередь офицеров получает заявку без текста, а обычный шёпот остаётся у первого получателя.

J1/J2/J3 и JT принимаются только напрямую по WHISPER. Они не подписаны и не дают доступа к переписи, реле или общему чату: это просьбы новичков, а не подтверждение личности, членства или ранга. Текст и метаданные могут прийти в любом порядке. Прежние J1/J2/J3, подписанные форматы и префикс не меняются; JT/JQ/JS/JX — дополнительные типы, старые клиенты их игнорируют. Для полной общей очереди нужны обновлённые адресат и офицеры, для текста письма — также обновлённый новичок. Системы королевских ворот и публичных хартий Olympus в Чиллзоне нет, поэтому дополнительных приоритетов от них здесь нет.

## Окно чата

Окно повторяет раскладку стандартного окна «Гильдия и сообщества». Пузырей нет, строки идут одной лентой.

**Шапка** справа вверху, как у Olympus, одна на все вкладки. Крупно — сколько всего участников во всех гильдиях «Чиллзон», мелко — сколько из них в игре, сколько гильдий и когда пришёл самый свежий отчёт. Наведение показывает счёт по каждой гильдии.

**Перепись.** Слева — список гильдий: сколько в игре из скольких и кто глава. Справа — карточка выбранной гильдии (сразу выбрана ваша): крупные числа, руководство (правый щелчок по имени — меню: шёпот или приглашение в группу), полоса классов в игре, столбики уровней, зоны полосками. Классы, уровни и зоны берутся только из свежего отчёта; зоны чужой гильдии видны, только если её репортёр ими делится. Внизу карточки — таблица всех, кто сейчас в игре, а строка «Все гильдии» над списком показывает их одной таблицей по всему объединению. Щелчок по заголовку колонки сортирует, повторный разворачивает порядок; сначала стоят старшие по уровню. Значок в колонке CZ, как и в панели чата, стоит у тех, у кого аддон точно есть. Зона есть только в таблице своей гильдии: у чужих по сети приходят лишь имя, класс, уровень и отметка аддона, а звание для них известно только у главы и офицеров из отчёта. Своя гильдия берётся из ростера, чужие запрашиваются, только пока список на экране, и обновляются раз в две минуты.

**Каналы слева:**

| Канал | Что это | Кому виден |
|---|---|---|
| «<ваша гильдия>» | обычный чат гильдии игры | всем в гильдии |
| «Офицеры гильдии» | офицерский чат гильдии игры | тем, кому игра разрешает его читать |
| «Чиллзон», «Офицеры», «Главы» | общий чат гильдий «Чиллзон» (`/cz1`–`/cz3`) | по рангу, как в таблице выше |

Под названием канала подписано, чей он: «чат гильдии» или «все гильдии». Так чат гильдии «Чиллзон» не спутать с общим каналом «Чиллзон». На канале с новыми строками стоит значок и число непрочитанных. В строках общих каналов после имени серым написана гильдия автора. Если гильдию автора строки из канала игры подтвердить нечем, вместо неё стоит серое `<?>` (см. «Канал игры для `/cz1`»).

**Люди справа.** Для чата своей гильдии — кто в игре; для офицерского — офицеры. Для общих каналов — главы и офицеры всех гильдий из переписи плюс все, кто писал в канал за последний час. Список сгруппирован по гильдиям. Кто не в игре, показан серым. Значок Chillzone между именем и уровнем — у человека есть аддон; подсказка пишет «есть» с версией, «нет» или «неизвестно». Про согильдийцев аддон знает по приветам H1: кто в игре, но за полторы минуты после входа не прислал привета, — без аддона. Про другие гильдии известно только «есть»: человек писал в общий канал подписанной строкой или прислал отчёт переписи; строка из канала игры отметку не ставит. Авторы строк из канала игры, чью гильдию подтвердить нечем, собраны внизу в группе «Гильдия не подтверждена». Правый щелчок по имени открывает меню: шёпот или приглашение в группу (тому, кто в игре). Счётчик «В сети: X из Y» под списком виден только в чатах своей гильдии: в обычном — по ростеру, в офицерском — по списку офицеров. В общих каналах счётчика нет: список справа неполный, а общий онлайн объединения показан в шапке окна. Список справа не ограничивает приём сообщений.

**Поле ввода:**

- Enter отправляет строку, курсор остаётся в поле. Пустой Enter или Esc убирают курсор.
- Tab и Shift+Tab переключают канал. Стрелки ↑ и ↓ листают 20 последних отправленных строк.
- Черновик у каждого канала свой.
- `/w Имя Фамилия текст` — шёпот. Другие команды здесь не работают: их пишут в обычном чате игры.
- Shift-клик по предмету в сумке или по ссылке в окне вставляет ссылку в поле.

**Enter, пока окно открыто,** ставит курсор в поле окна, а не в чат игры. Чтобы написать в чат игры, закройте окно или нажмите `/`. В бою привязка Enter не меняется до конца боя. В режиме геймпада Enter не перехватывается.

**Копии в чате игры.** Галочка «Дублировать в чат игры» управляет дополнительными копиями строк. Щелчок по метке канала (`[Чиллзон]`, `[Офицеры]`, `[Главы]`) в чате игры открывает поле этого канала в той же вкладке, как штатный `[Гильдия]`. Поле разовое: после Enter или Escape следующий Enter снова открывает обычный чат игры. Штатному полю аддон меняет только прозрачность. Окно аддона открывается, если игрок уже набирает текст в штатной строке или установлен Chattynator, у обычных вкладок которого нет окна чата игры.

**Регистр тегов гильдий.** По умолчанию короткие теги имеют вид `<Чз>`, `<ЧзН>` и `<Зн>`. Галочка «Теги гильдий прописными» в настройках переключает их на `<ЧЗ>`, `<ЧЗН>` и `<ЗН>`. Выбор сохраняется отдельно для каждого персонажа и действует в окне Chillzone и в чате игры. История окна перерисовывается сразу; уже выведенные строки игры остаются прежними, новые строки и повторный вывод истории учитывают выбор. Полные названия других гильдий и цвета не меняются. В игре можно проверить оба положения галочки, повторный вход и отсутствие наложения на соседние настройки.

Цвет текста общих каналов выбирается в настройках и применяется в окне аддона, во вкладке «Чиллзон» и в копиях в чате игры. Метка канала и имена сохраняют свои цвета.

**Чиллзон в настройках каналов игры.** Под игровыми списками появляется собственная строка «Чиллзон». Её флажок включает копии доступных общих каналов в текущей вкладке; снятие последнего выключает дублирование, сохраняя историю. При выключенном дублировании включается только выбранная вкладка. Квадрат цвета открывает свою палитру с общей настройкой цвета; изменения сохраняются сразу. В отличие от обычных флажков игровых каналов, этот флажок управляет копиями Chillzone. Модуль `ChatConfig.lua` создаёт только свои дочерние кадры, без хуков и изменений игровых таблиц, обработчиков или `ColorPickerFrame`. В бою, при Chattynator, без нужного API, для журнала боя и при нехватке места строка скрыта. Без клиента проверены логика и изоляция в симуляторе; внешний вид и taint в игре не проверены.

**Вкладки чата игры.** Копии строк можно выводить сразу в несколько вкладок: в настройках под «Дублировать в чат игры» кнопка «Вкладки в чате игры» открывает список с галочками. Щелчок переключает галочку, оставляя список открытым; повторный щелчок по кнопке закрывает список. Можно выбрать и основное окно вместе с другими вкладками. Последнюю галочку снять нельзя; все копии выключает настройка «Дублировать в чат игры». Команда `/chillzone window <название>` заменяет весь выбор одной вкладкой, пустой аргумент — основным окном. Вкладки создают в самой игре (правый щелчок по вкладке чата). Журнал боя и закрытые невыбранные окна в список не попадают. Выбранная закрытая или переименованная вкладка остаётся в списке красной, чтобы можно было снять её галочку. Строки продолжают идти в остальные выбранные вкладки; если недоступны все, одна копия идёт в основное окно и о каждой пропавшей вкладке один раз пишется предупреждение. Кнопка выделяется красным, если хотя бы одна выбранная вкладка недоступна. При нескольких выбранных вкладках кнопка показывает их число, а подсказка — названия. Строки и `/chillzone history` пишутся во все выбранные доступные вкладки. В штатном чате галочки в настройках самой вкладки на них не влияют, и вкладка, скорее всего, не мигает при новых строках. Свой список вместо `UIDropDownMenu` — из-за taint; выбор вкладок не меняет окна чата игры. Выбор хранится для каждого персонажа; прежняя одиночная настройка переносится автоматически.

**Вкладка «Чиллзон».** В общем канале окна Chillzone нажмите «Вкладка чата». Вне боя кнопка создаёт или выбирает пристыкованную вкладку «Чиллзон» и закрывает окно аддона. Нажмите Enter или щёлкните по полю «Чиллзон:», чтобы отправить текст всему союзу без `/cz`. При смене вкладки или фокусе в обычном вводе штатное поле возвращается. Кнопка отмечает вкладку в списке «Вкладки в чате игры» и не снимает другие галочки, поэтому строки продолжают идти туда, куда шли раньше. Если дублирование было выключено, оно включается только для этой вкладки. Снятая галочка или выключенное дублирование убирают у вкладки и строки, и поле ввода. Вкладка, открытая прежней версией, переносится в список автоматически.

**Создание вкладки по ПКМ.** Правый щелчок по метке `[Чиллзон]`, `[Офицеры]` или `[Главы]` открывает своё меню с пунктом «Добавить вкладку». Он создаёт штатную вкладку «Чиллзон», включает дублирование и добавляет её к выбранным назначениям. Повторное создание использует свободное название «Чиллзон 2», «Чиллзон 3» и так далее: поле ввода есть только у вкладки «Чиллзон», остальные получают лишь копии строк. В бою и при полном ряду создание недоступно; существующие окна не перезаписываются. Щелчок мимо или повторный ПКМ закрывает меню. В Chattynator вкладки добавляют через его настройки, как и специальную вкладку из #45.

**Enter во вкладке «Чиллзон».** Поле «Чиллзон:» есть только у отмеченной в настройке вкладки «Чиллзон» и у специальной вкладки Chattynator: Enter фокусирует его, следующий Enter отправляет текст в общий канал союза. На основной и других отмеченных вкладках настройка «Вкладки в чате игры» управляет только выводом: строка ввода остаётся штатной, а в союз пишут через `/cz текст` или щелчком по метке `[Чиллзон]`. Выбор другой вкладки сразу возвращает штатный ввод. Доступ к союзу и включённый общий чат обязательны. Слэш в начале строки сразу передаёт ввод штатному `ChatFrameUtil.OpenChat` (на старых клиентах — `ChatFrame_OpenChat`): `/г`, `/с`, `/g`, `/s`, `/w`, `/cast` и остальные команды разбирает сама игра, без предварительного Escape. Вставленная целиком команда тоже передаётся игре; слэш внутри обычного сообщения остаётся текстом. Команда не отправляется в союз и не остаётся в его черновике.

Enter ловит кнопка `ChillzoneChatKey` через `SetOverrideBindingClick`: только клавиши действия «Открыть чат», только пока поле на экране и никогда в режиме геймпада. Привязка общая с окном Chillzone, открытое окно важнее вкладки. Менять привязку в бою нельзя, поэтому смена вкладки в бою применяется к Enter после боя. Скрипты, атрибуты и методы игрового поля не меняются. `ChatFrameUtil.SetChatFocusOverride` не используем: он забирает любой `OpenChat` без вкладки и без слэша, поэтому шёпот Battle.net, клавиши ответа и ссылки из интерфейса попадали бы в поле союза. Они идут в штатное поле, а поле союза уступает ему место до закрытия. Отсутствие taint проверяют в игре.

**Hepega Team Smile Chat 0.9.0.** Кнопка W в поле «Чиллзон:» открывает установленное меню смайлов и вставляет выбранный код в это поле. В обычных игровых вкладках Hepega сам отображает смайлы.

**Chattynator.** В версии с API `RegisterCustomTab` включите «Чиллзон» через «Специальные вкладки» в настройках Chattynator. Это делается один раз для профиля. Вкладка показывает историю и новые сообщения общего канала, а её поле отправляет текст по Enter. Если окон Chattynator несколько, Enter принадлежит окну, где вкладку выбрали последней: обычная вкладка другого окна скрывает поле и возвращает штатный ввод, даже когда специальная вкладка ещё видна. Черновик сохраняется, выбор специальной вкладки снова показывает поле. При включённой замене смайлов в Hepega 0.9.0 вкладка показывает картинки в истории и новых строках. Анимированные смайлы показаны первым кадром. Дополнительные копии, история и отладка направляются в выбранные обычные вкладки через API Chattynator. Если вкладка фильтрует сообщения аддонов, разрешите Chillzone через «Настройка вкладки», «Аддоны», «Конкретные аддоны».

Журнал боя и временная вкладка поиска Chattynator недоступны для выбора копий. Если API выдаёт ошибку при выводе, строка целиком, с цветом и временем, сохраняется в основном окне один раз; исправные выбранные вкладки продолжают её получать. Выбор не сбрасывается, и после восстановления API копии снова идут в выбранные вкладки. Это относится и к `/chillzone history`. Первая ошибка API за сеанс записывается в журнал.

В специальной вкладке Chattynator и в основном окне Chillzone щелчок левой кнопкой по имени в сообщении готовит `/w` в своём поле, правой — открывает игровое меню персонажа. Shift-клик по предмету из сумки вставляет ссылку в активное поле Chillzone. Ссылку в сообщении можно открыть щелчком или вставить в поле через Shift-клик.

**Согильдийцы без аддона.** Автор сообщения общего канала (`/cz` или `/cz1`, в том числе из окна Chillzone) после подписи отправляет читаемую копию `[Чиллзон] текст` в обычный `/g` своей гильдии. Chillzone с этим обновлением скрывает копию и в игровом чате, и в истории чата гильдии: остаётся одна строка общего канала. Это не зависит от порядка доставки обычного и аддонного сообщений; выключенный общий чат и игнор тоже сохраняются. В старых версиях аддона копия будет видна до обновления. Сообщения `/cz2` и `/cz3`, а также принятые сообщения других авторов в `/g` не копируются. Для этой копии метка `[Чиллзон] ` в начале обычной строки гильдии зарезервирована.

**Настройки** (вкладка с шестерёнкой): общий чат вкл/выкл, «Общий чат через канал игры» (включено), «Скрывать неподтверждённых» (выключено), дубль в чат игры, время у строк, круги на карте, делиться зонами, кнопка у миникарты.

Кнопку у миникарты создаёт встроенная LibDBIcon-1.0, объект запуска `Chillzone`
зарегистрирован в LibDataBroker-1.1. Поэтому её могут подхватывать сборщики кнопок
и панели LibDataBroker. Левый щелчок открывает окно, правый переключает круги на
карте, перетаскивание меняет положение. Скрытие по-прежнему доступно в настройках
и через `/chillzone minimap`; прежнее положение переносится автоматически.

**Кнопка CZ на карте.** Левый щелчок показывает или скрывает круги; приглушённый значок означает, что они скрыты. Это та же настройка, что `/chillzone map on|off` и галочка в настройках, она сохраняется после выхода. Кнопка остаётся доступной при скрытых кругах и работает без OpenMap и Questie. Если другой аддон загрузил совместимый `Krowi_WorldMapButtons`, CZ занимает место в общем ряду. В остальных случаях используется место в левом верхнем углу карты. Аддоны со своей независимой расстановкой кнопок могут пересекаться с этим местом: удерживая Shift, перетащите CZ; положение сохранится относительно размеров карты. Shift и правый щелчок возвращают автоматическое расположение. В режиме геймпада кнопка скрыта, как и круги.

**OpenMap.** На бесшовной карте сводный круг Chillzone смещён влево от центра зоны, чтобы не перекрывать метку друзей и согильдийцев OpenMap. Сдвигаются и значок, и область его подсказки. По умолчанию расстояние рассчитано на стандартный значок OpenMap: размер кружка с обводкой учитывается автоматически, между метками остаётся небольшой зазор. При обычных масштабах библиотеки расстояние между центрами составляет около 21–34 точек интерфейса. Если значки OpenMap увеличены, включите «Увеличенный отступ в OpenMap» в настройках Chillzone (`/chillzone settings`): отступ сразу увеличится на 9 точек и сохранится после выхода. Этот режим оставляет место под значки OpenMap вплоть до двойного размера. Публичный API OpenMap не сообщает выбранный размер: автоматического определения размера или пересечений нет. На обзоре сдвиг не уменьшается до наложения областей наведения. На обычной карте круг остаётся в центре зоны независимо от галочки. Состав гильдий и числа не меняются: Chillzone по-прежнему показывает участников объединения, а не только своей гильдии. Координаты игроков OpenMap не затрагиваются.

**Журнал** доступен любому игроку, в том числе без гильдии. Кнопка «Начать запись» включает диагностику шёпотов, «Остановить запись» выключает её. В обычный чат запись не выводится. Собираются API, адресат, префикс аддон-сообщения, доступное место вызова и системные ответы независимо от давности шёпотов Chillzone. Текст личных сообщений и содержимое пакетов не читаются. Используются безопасные пост-хуки отправки; если API или источник недоступен, это видно в отчёте. Совпадение адресата системной ошибки с последним шёпотом отмечается отдельно и не считается подтверждением доставки.

Кнопка «Скопировать отчёт» открывает выделенный текст для Ctrl+C: версия, персонаж, реалм, состояние наблюдения за API, счётчики, до 1000 последних записей и сохранённые ошибки. Новые события не меняют этот снимок, пока игрок копирует. Свежие ошибки имеют время и версию и попадают в хронологию; у прежних записей явно указано, что время и версия неизвестны. «Очистить» удаляет журнал и сохранённые ошибки. Для разбора достаточно одного отчёта; отключать остальные аддоны не требуется.

**Отладка** доступна только главам и офицерам. Обновляется раз в 5 секунд. На ней видно:

- я: ключ имени, версия, гильдия и звание; офицер ли я и откуда это известно — по флагу звания; если игра не отдала права, это указано отдельно и офицерский доступ не предоставляется; уровень в чате и роль в связи;
- реле: реле ли я и через кого уходят мои сообщения; счётчики пересылок; сколько сообщений ждёт реле; когда я как репортёр регистрировался у реле. Дальше — все известные реле: состояние («отвечает», «ждём ответа», «не в игре» и сколько ещё), «в приоритете» у главы и офицеров главной гильдии, почему я им доверяю (я сам, глава или офицер главной гильдии, участник главной гильдии). Подсказка у реле — когда отвечало, когда спрашивали, от кого я о нём узнал. Если я реле — какие репортёры гильдий у меня зарегистрированы и не устарела ли регистрация;
- перепись моей гильдии: кто репортёр; согильдийцы с аддоном, их версия (чужая — красным), делятся ли зонами, реле ли они, когда последний раз отзывались;
- отчёты гильдий: от кого пришёл последний отчёт и когда, «!» при расхождении руководства, сколько отчётов отклонено и почему;
- счётчики сообщений аддона и чата, очередь отправки;
- последние ошибки аддона (полный текст — в подсказке и в `/chillzone log`).

## Как это работает

На WoW: Forever сообщения аддонов в пользовательском канале **не доставляются**. Доставляются три вида сообщений:

- аддон-сообщения внутри гильдии (GUILD);
- аддон-шёпот (WHISPER). Шептать нужно на «Имя Фамилия» без реалма;
- обычный текст в канале, только от нажатия клавиши (Enter или слэш-команда). Аддон отправляет туда строки `/cz1` вторым путём, но ничему из канала не доверяет: пользовательский канал может открыть `/join` любой, кто знает название, и писать туда что угодно.

Отсюда схема:

1. **Внутри гильдии** клиенты с аддоном раз в минуту здороваются по GUILD. Репортёр выбирается сначала среди доступных глав и офицеров, затем среди остальных подходящих участников. Внутри этой группы сохраняются выбор по имени и предпочтение согласившихся делиться зонами (`/chillzone zones on`). Кого свежий ростер показывает вне игры, не выбирают, даже если его привет ещё не устарел. В блокировке чата и ещё 70 секунд после неё новым репортёром стать нельзя: приветы могли не доходить, и клиент выбрал бы сам себя. Действующий репортёр в блокировке свою роль сохраняет.
2. **Репортёр** раз в ~3 минуты отправляет отчёт о гильдии **ретранслятору** шёпотом. Если ничего не изменилось, отчёт уходит не чаще раза в 10 минут. Отчёт уходит сразу двум отвечающим реле из тройки (`Relay.Out`, второе — `Relay.Pick` без первого), если второе есть: реле с выключенным аддоном молчит, не выходя из игры, сервер об этом не сообщает, а тайм-аут опроса наступает позже, чем отчёт ещё можно переотправить. Реле и получатели отбрасывают вторую копию по тем же отметкам повторов. Строки чата идут через одно реле, как раньше. Чужой отчёт, пришедший реле вне тройки, оно по-прежнему переносит в тройку одному реле.
3. **Ретранслятор** пересылает подписанный отчёт репортёрам остальных гильдий. Репортёр обновляет регистрацию каждые 15 секунд не более чем у трёх кандидатов. Сертификат должен подтверждать именно его имя и гильдию; аренда без обновления истекает за 60 секунд. При смене репортёра прежний ещё две минуты пересылает гильдии то, что ему шлют реле, и называет им преемника (`RU`), а реле передают аренду ему. Ответ на опрос ждём 30 секунд после фактической отправки: задержка своей очереди и блокировка чата не делают реле недоступным. После тайм-аута реле исключается на минуту, затем проверяется повторно; подтверждённый сервером офлайн исключает адресата на 10 минут.
4. **Репортёр** раздаёт исходные подписанные пакеты своей гильдии по GUILD. Строки чата принимаются только от выбранного репортёра (при смене — и от прежнего), а подпись автора независимо проверяется каждым получателем.
5. **Отчёт переписи идёт и в обход репортёра.** Клиент берёт отчёт у любого согильдийца, если он новее сохранённого. Реле главной гильдии, получив новый для себя чужой отчёт, сразу отдаёт его своей гильдии по GUILD и не ждёт её репортёра: тот может молчать или быть зарегистрирован у другого реле. Так же пригождается кэш соседа, когда репортёр сам знает меньше. Название гильдии и время отчёта читаются до проверки подписи, поэтому старые отчёты и повторы отбрасываются без неё и без записи в журнал. До проверки подписи доходит не больше 12 таких отчётов в минуту от одного отправителя (`Config.RG_SIDE_PER_MIN`); неизвестный сертификат автора при этом не запрашивается, пакет только ждёт его. Принятый так отчёт виден в журнале строкой «отчёт ... принят от ...: он не репортёр гильдии». Репортёру отчёт по-прежнему уходит по аренде, и он пересылает его гильдии: клиенты старых версий берут пересылку только у него.
   **На Q1 отвечают и помощники.** Первым по-прежнему отвечает репортёр. Если он молчит или знает меньше соседей, недостающее досылают до трёх помощников (`Config.Q1_HELPERS`, `Census.Helpers`): согильдийцы на связи с сертификатом и версией новее последней вышедшей без помощников (`Config.LAST_WITHOUT_HELPERS`; граница одна для всех клиентов, а не своя версия), которые слушают гильдию дольше трёх минут, в общей для всех очереди «офицеры, делящиеся зонами, имя». Спросивший в очередь не входит. Пока номер аддона не выше `LAST_WITHOUT_HELPERS`, помощников нет вовсе: вышедшие клиенты с тем же номером обязанностей не знают, а номер поднимается на релизе. Первый помощник ждёт 45 секунд (`Config.Q1_HELPER_WAIT`) после Q1 или последнего отчёта, показанного гильдии, каждый следующий — на 20 секунд дольше (`Config.Q1_HELPER_STEP`). Помощник отдаёт только пакеты, которых гильдия в этом раунде ещё не видела байт в байт, свежие первыми, и не больше 10 за раз: лимит получателя `RG_SIDE_PER_MIN` минус запас на рассылку реле. Если чужая копия ушла раньше, его ещё не отправленный ответ снимается с очереди. Чужой пакет считается показанным, только если отправитель за минуту не превысил тот же лимит: сверх него получатели пакет не взяли бы. Раунд открывается не чаще раза в `Config.Q1_GAP` на всю гильдию, и помощник отвечает не чаще того же срока. В журнале ответившего помощника — строка «ответ на Q1 вместо репортёра: N из M отчётов». Формат сообщений не менялся.
   **Устаревший отчёт берётся у автора напрямую** (`Pull.lua`). Отчёт другой гильдии старше 12 минут (`Config.PULL_AFTER`) не дошёл ни через одно реле: живой репортёр за это время отчитался бы хотя бы раз (`REPORT_IDLE` и минута на чтение ростера). Вкладка считает отчёт свежим 15 минут (`Config.FRESH`), и на запрос остаётся три минуты. Тогда репортёр гильдии шепчет `RQ` участнику той гильдии в обход реле: сначала автору последнего отчёта, затем случайным из главы, офицеров и связных, которые по тому отчёту были в игре, всего до трёх (`Config.PULL_TRIES`). Если отчёт так и не обновился, через 5 минут после репортёра (`Config.PULL_HELPER_DELAY`) спрашивает и первый помощник, какой бы версии ни был репортёр: шёпот виден только адресату, и узнать, спрашивает ли репортёр и отвечают ли ему, помощник не может. Репортёр может быть старой версии, в блокировке чата или без ответа от своих адресатов. Когда отвечать некому, гильдия шлёт за раунд до шести шёпотов вместо трёх. Ответ `RA` — отчёт гильдии ответившего, подписанный им самим. Он принимается только от того, кого спросили, только о той гильдии и только в течение 45 секунд после отправки запроса (`Config.PULL_WAIT`), и только если отчёт новее сохранённого; остальное отбрасывается до проверки подписи. Дальше пакет проверяется как от реле (автор пакета — сам ответивший, гильдия его сертификата — гильдия отчёта) и уходит гильдии спросившего по GUILD. Кого сервер назвал «нет в игре», не ждут. Если не ответил никто, следующий раунд — через 10 минут, пауза растёт вдвое до часа (`Config.PULL_RETRY`, `PULL_RETRY_MAX`). Отвечающий отвечает только участнику другой гильдии объединения, одному спрашивающему не чаще раза в 5 минут, всем вместе не больше трёх раз в минуту (`PULL_SERVE_GAP`, `PULL_SERVE_PER_MIN`: ответ с сертификатом — около восьми кусков), в блокировке чата молчит и своей гильдии ничего не рассылает. Отвечает любой обновлённый участник гильдии. Репортёр (или бывший, до перезагрузки интерфейса) отдаёт свой последний отчёт, пока тот моложе 12 минут. Иначе отвечающий подписывает отчёт своей гильдии по своему ростеру, с числом согильдийцев с аддоном по своим приветам и своей версией, и 5 минут отдаёт его повторно, не подписывая новый (`Config.PULL_ANSWER_KEEP`). Этот отчёт не уходит ни через реле, ни своей гильдии и не меняет отчёт репортёра. Подписывает только тот, у кого свежий ростер и кто слушает приветы гильдии дольше трёх минут; если очередь подписи занята или подпись не удалась, он молчит, и спрашивают следующего. Отвечают только отчётом новее, чем у спросившего. Глава, офицеры и связные в таком отчёте те же, что у репортёра с тем же ростером, поэтому противоречия между ними нет. В журнале: «отчёт ... устарел на N мин, запрашиваю его напрямую», «отчёт ... получен напрямую от ...», «отчёт своей гильдии отдан напрямую: ...», в `/chillzone status` — строка «отчёты напрямую». `RQ` и `RA` — новые типы сообщений; клиенты 0.13.1 и раньше их молча отбрасывают.
6. **Строка чата** подписывается автором один раз и уходит по GUILD своей гильдии и через реле остальным. Подтверждать её у автора личным шёпотом не нужно. Повторы отбрасываются. Строка `/cz1` дополнительно уходит обычным текстом в канал игры (ниже). Скрытые каналы старых версий (`ChillzoneA`, `ChillzoneH`) больше не используются: клиент из них выходит.

Свою гильдию каждый клиент видит только по своему ростеру. Чужие отчёты о ней игнорируются.

### Канал игры для `/cz1`

Обновлённые участники объединения входят в обычный канал игры `ChillzoneChatA` (Альянс) или `ChillzoneChatH` (Орда), `Config.CHANNEL`. Имена старых скрытых каналов не годятся: клиенты до 0.13.1 выходят из них и прячут их строки. Вход идёт после того, как игра откроет свои каналы (не позже 15 секунд после входа), и повторяется раз в минуту, если клиент оказался вне канала. Проверка в игре показала, что вход из аддона номера каналов игры 1–4 не сдвигает (наш канал берёт первый свободный номер) и в окна чата канал сам не добавляет, поэтому каналы не переставляются; без членства в объединении или при выключенной настройке клиент из канала выходит. Пароль или бан канала откладывают повторный вход на 10 минут. Выключатель для всей сборки — `Config.CHANNEL_CHAT`, для персонажа — галочка «Общий чат через канал игры».

**Отправка.** Строка `/cz1` (и строка общего канала из окна) уходит двумя путями. Сначала, в том же нажатии Enter, каждая часть строки обычным текстом уходит в канал игры: игра принимает такой текст только от нажатия клавиши, поэтому эта отправка не переносится в таймер. Затем, как и раньше, строка подписывается и уходит по GUILD и через реле. В блокировке чата (подземелье, бой) канал не используется, строка идёт только подписанным путём и уходит после выхода. Форматы `S1` и `M1` не менялись; старые клиенты получают строку прежним путём и канала не замечают. `/cz2` и `/cz3` в канал не уходят никогда.

**Бюджет канала.** Сервер пропускает 3 строки игрока за скользящие ~30 секунд; лишние никому не раздаёт и отвечает автору уведомлением `THROTTLED`, эха у них нет. Аддон ведёт свой счёт: строки, вернувшиеся эхом (в том числе набранные игроком в канал вручную), плюс отправленные и ещё ждущие эха, не больше `Config.CHANNEL_BUDGET` (3) за `Config.CHANNEL_WINDOW` (35) секунд. Строка идёт в канал целиком или не идёт: если частей больше, чем осталось в бюджете, она уходит только подписанным путём и попадает в счётчик «сверх бюджета». `THROTTLED` от сервера — истина: до конца окна в канал не пишем, каким бы ни был свой счёт (лимит может оказаться общим на все каналы игрока). По сохранённой истории чата лимит задел бы около 2 из 100 строк `/cz1`.

**Состояние канала** видно в `/chillzone status`: исправен, под сомнением, сломан до перезахода персонажа или отправка выключена до перезагрузки интерфейса. Клиент может не знать, что он вне канала: после бана ему не приходит ни одного уведомления, канал остаётся в списке, а отправки молча пропадают или получают `THROTTLED`; повторный вход отвечает `NOT_ALLOWED_IN_CHANNEL`, и помогает только перезаход персонажа. Надёжный признак — нет эха своей строки. Поэтому каждая своя строка ждёт эха 5 секунд: одна строка без эха — канал под сомнением, две подряд (или два `THROTTLED` подряд при свободном своём бюджете, `NOT_ALLOWED_IN_CHANNEL` при входе, пометка «выключен» в списке каналов игры) — сломан. В сломанный канал аддон не пишет и заново не входит, игрок один раз видит подсказку перезайти персонажем; строки `/cz1` идут через реле. Состояние переживает `/reload` и сбрасывается при входе персонажа. Любое эхо своей строки возвращает канал из сомнения в исправные.

**Окно ошибки игры.** Если отправка в канал всё же оказалась вне нажатия клавиши, игра показывает окно «ошибка интерфейсной операции» и шлёт `ADDON_ACTION_BLOCKED` с именем аддона. Тогда отправка в канал выключается до перезагрузки интерфейса, а событие пишется в журнал.

**Без сертификата** строка `/cz1` уходит только в канал игры. Аддон сообщает об этом в чате один раз за 10 минут (или при смене причины) и, если за 5 секунд своя строка не вернулась из канала (нет эха) или сервер ответил `THROTTLED`, предупреждает, что она, возможно, не дошла. Если на строку не хватает бюджета канала, она не отправляется вовсе: аддон называет, через сколько секунд можно повторить, текст остаётся в поле ввода окна.

**Приём.** Строки нашего канала аддон скрывает из окон чата игры фильтром, как и уведомления канала; вместо них игрок видит привычную строку `[Чиллзон] <тег> [Имя]: текст`. Гильдия автора строки из канала определяется по имени: свой ростер, затем действующий сертификат участника объединения, затем руководство (глава, офицеры, связные) из свежих отчётов переписи, затем поимённый онлайн, если он уже загружен. Если ничего не подошло, вместо тега стоит серое `<?>`. Галочка «Скрывать неподтверждённых» (по умолчанию выключена) убирает такие строки совсем. Класс автора берётся из GUID события, если игра его отдаёт.

**Сведение копий.** Одна и та же строка может прийти дважды: из канала и подписанной. Пара ищется среди показанных за `Config.CHAT_DEDUPE` секунд строк того же автора: сначала по точному тексту без цветовых кодов, затем с учётом фильтра брани. Фильтр брани игры у получателя (и у автора — в эхе своей строки) меняет текст строки канала прямо в событии: слово заменяется знаками `!@#$%^&*`. Участок из двух и больше разных таких знаков в копии из канала совпадает с любым текстом длиной от одного байта, остальное сравнивается байт в байт. Первая копия показывается, вторая только гасит её. Если подписанная копия пришла после строки из канала, `<?>` у показанной строки заменяется подтверждённой гильдией. Два одинаковых сообщения подряд остаются двумя строками. Своя строка показывается один раз: по подписи или по эху канала, что придёт раньше.

**Счётчики путей.** `/chillzone status` и вкладка «Отладка» показывают, сколько строк пришло только каналом, только подписанным путём и обоими, сколько своих строк вернулось эхом из скольких отправленных, сколько неподтверждённых скрыто, сколько своих строк ушло сверх бюджета канала и сколько строк пришло подписью без копии из канала от авторов, которых канал в этой сессии уже слышал. Последнее — признак глухого канала у себя (забаненному не приходят ни строки, ни уведомления); аддон его только считает и пишет в журнал. Отдельная строка `/chillzone status` показывает имя, номер и состояние канала, свободный бюджет, отправки, эхо, строки без эха, `THROTTLED`, чужие строки, владельца канала, включены ли объявления входа и выхода и последнее уведомление. Уведомления канала (вход, выход, смена владельца, объявления, пароль, бан, мут) пишутся в журнал.

**Поимённый онлайн** идёт не через реле, а шёпотом напрямую: рассылать его всем было бы слишком дорого, а нужен он только тому, кто его смотрит. Зритель шепчет `OQ` с отпечатком своего сертификата репортёру гильдии, чьё имя пришло с отчётом. Отвечающий проверяет сертификат и отправляет `OL` из своего ростера страницами до четырёх кусков, поэтому в списке есть и игроки без аддона. В ответе только имя, класс, уровень и отметка «есть аддон», которую отвечающий знает по приветам `H1` в своей гильдии, без зон. Страница принимается только от того, кого спросили, и только если его сертификат той же гильдии. Если адресат молчит 20 секунд, зритель спрашивает следующего (случайного главу, офицера или связного в игре по отчёту), всего до трёх за запрос, а после неудачи повторяет не раньше чем через минуту. Клиент отвечает одному зрителю не чаще раза в 45 секунд и отдаёт не больше двух списков одновременно; страницы встают в очередь по одной и не задерживают чат. В блокировке чата клиент не отвечает, и зритель спрашивает другого. Пока зритель ждёт список, которого у него ещё нет, запрос виден в строке операций внизу окна; плановое обновление уже показанного списка идёт фоном и туда не попадает.

**Новая версия аддона.** Клиент узнаёт версии других игроков из приветов H1 своей гильдии и из отчётов R1: в конце отчёта — версия аддона репортёра. Версия считается вышедшей, когда новее своей её назвали хотя бы два разных игрока (`Config.UPDATE_SOURCES`). Тогда игрок с устаревшим аддоном видит строку в чате (раз за сессию, не раньше 20 секунд после входа), просьбу обновиться в заголовке окна и строку в `/chillzone status`. Услышанное хранится в `ChillzoneDB` две недели. После обновления предупреждение пропадает само. Версии с хвостом вроде `0.9.0-dev` ни с чем не сравниваются. Аддон ничего не отправляет ради этого и никому не шепчет. Версии до 0.8.0 включительно этого кода не знают: их владельцев нужно предупредить вручную.

**Что идёт сейчас и обновление по запросу.** В нижней полосе окна справа, рядом с кнопкой «Обновить», стоит строка состояния. Жёлтая точка пульсирует, пока аддон ждёт ответа или считает подписи. Красная называет причину, из-за которой работа стоит: нет сертификата или игра запретила отправку. Зелёная показывает итог обновления. Подсказка перечисляет всё активное и свежесть ростера, переписи и реле. Приветы, плановые чтения ростера и продление аренд там намеренно не показываются. Строку опрашивает только открытое окно.

Кнопка «Обновить» и `/chillzone refresh` работают не чаще раза в 30 секунд (`Config.REFRESH_GAP`). Сначала читается ростер, затем обычный участник спрашивает отчёты у репортёра (Q1, не чаще `Config.Q1_GAP`), а репортёр публикует свой. После этого опрашиваются реле, а офицеры запрашивают заявки. Новых типов сообщений нет. Реле, признанные недоступными, такими и остаются, в отличие от `/chillzone relay ping`: вернувшийся в тройку мёртвый реле задержал бы чат. Репортёр отвечает на Q1 не чаще раза в две минуты и молчит при пустом кэше, поэтому итог «Новых отчётов нет» не считается ошибкой. Если репортёр молчит, отчёты присылают помощники не раньше чем через 45 секунд, а строка операции ждёт первого отчёта только 30 (`Config.CENSUS_WAIT`): итог «Новых отчётов нет» тогда появляется раньше, чем они придут. Повторное обновление раньше этого срока отчёты не запрашивает: итог называет, через сколько секунд это станет возможно, а то же время видно в подсказке кнопки.

### Кто ретранслятор

- Подтверждённый сертификатом участник главной гильдии «Чиллзон» с аддоном; при ограничении по званию — глава, офицер или связной.
- Имена из ответов реле являются подсказками для поиска. Они не создают доверие без сертификата.
- Ручные разрешения и неподтверждённые отчёты не дают доступа в протоколе 0.4; список `RELAYS` в `Config.lua` убран.

Все клиенты одинаково упорядочивают реле: **сначала главы и офицеры главной гильдии** по свежему сертификату, затем остальные, внутри — по имени. Репортёры регистрируются у трёх доступных реле сверху списка, сообщения уходят через отвечающее реле из этой тройки, офицеры первыми, а отчёт переписи — ещё и через второе отвечающее. Если офицеры не отвечают, выбирается рядовой; пока офицера из тройки ещё не спрашивали, строка ждёт его ответа в очереди, иначе она могла бы уйти рядовому без аренд и дойти только до своей гильдии. Внутри выбранной группы сохраняется распределение по хешу гильдии и времени. Участник главной гильдии рассылает сам, только если у него зарегистрированы репортёры других гильдий; иначе отправляет реле из тройки, как все. Новая гильдия сначала знает мало сертификатов главной и может зарегистрироваться у рядового вне общей тройки. Такой участник рассылает своё и зарегистрированным у него, и через реле из тройки, а спросившему отдаёт сертификаты своей тройки, после чего тот переходит на общую тройку. Так же первые десять с половиной минут после входа поступает и реле из тройки: репортёры других гильдий регистрируются у него заново не сразу, а заметивший его выход ждёт до десяти минут. Конфликт неподтверждённых отчётов не меняет права. Постоянный опрос выполняют репортёры; обычный читатель не опрашивает весь союз. Роль в сертификате действует 15 минут после выдачи, поэтому репортёр гильдии передаёт ей новые сертификаты общей тройки: иначе у молчавшего автора офицеры тройки считались бы рядовыми, и его первая строка ушла бы реле без аренд.

### Проверка по званию (сейчас выключена)

Пока звания не розданы, `TRUST_ANY_MEMBER = true`: репортёром и реле может быть любой участник. Чтобы вернуть проверку, поставьте `false` в `Chillzone/Config.lua`. Тогда:

- репортёр гильдии — только её глава, офицер или связной; если никого из них нет в игре, репортёра нет, и перепись и строки других гильдий ждут;
- реле — только глава, офицеры и связные главной гильдии;
- пересылки по GUILD по-прежнему требуют выбранного репортёра и верной подписи; настройка не отключает проверку авторства.

Связной — персонаж со званием `RELAY_RANK` (по умолчанию «Ветеран»), которое сравнивается целиком без учёта регистра и пробелов по краям. Смена звания учитывается по свежему ростеру и новому сертификату; извне отзыв узнаётся после обновления. Связной не получает офицерских прав или права выдавать сертификаты, но видит пересылаемый текст.

## Настройка

Всё, что настраивает автор, лежит в `Chillzone/Config.lua`:

```lua
C.GUILD_TOKEN = "Чиллзон"  -- первоначальная подсказка /who для набора; не допуск в сеть
C.MAIN_GUILD = "Чиллзон"   -- главная гильдия
C.OFFICER_RANK = 1         -- значение для чистых сборщиков данных, не запасной допуск
C.RELAY_RANK = "Ветеран"   -- звание связных ("" — только глава и офицеры)
C.TRUST_ANY_MEMBER = true  -- репортёр и реле — любой участник; false — по званию
```

Списки `GUILDS` и `EXTRA_GUILDS` заменены подписанным составом объединения. Первоначальный поиск использует подсказку `GUILD_TOKEN`; известные гильдии с другими названиями и подсказки J2 проверяются отдельными запросами `/who`, по одному на щелчок.

**Корень доверия задаёт офицер.** В каждой гильдии один раз офицер выполняет `/chillzone trust init`: его ключ становится корнем, остальные офицеры получают корень сами. Аддон сначала 10 секунд спрашивает гильдию и не создаёт второй корень, если он уже есть. Без корня сертификаты не выдаются, и гильдия в обмене не участвует.

**Соединение гильдий.** `/chillzone link Имя Фамилия` ставит запрос в очередь, затем отдельно сообщает об отправке. Запрос повторяется сам раз в 15 секунд; на подтверждение есть три минуты после отправки. Получатель проверяет имя и гильдию и выполняет `/chillzone accept Имя Фамилия`: у него подтверждается корень, инициатор получает ответ. Если ответ потерялся, тот же запрос получает повторный ответ без второго `/accept`. Повторы не создают доверие к новому или отозванному корню. Сообщение о подтверждённой связи у инициатора означает, что обратный ответ действительно получен. Подробности совместимости — в [SECURITY.md](SECURITY.md#первое-соединение).

**Составом объединения управляет только текущий глава «Чиллзон».** На вкладке «Объединение» он запрашивает связь с представителем гильдии или подтверждает входящий запрос кнопкой «Добавить в объединение». Глава или офицер гильдии вне объединения видит на этой вкладке другой вид: корень доверия своей гильдии и кнопку запроса связи. Запрос уходит главе, чьё имя записано в `C.MAIN_GUILD_LEADER`: это только адрес, прав имя не даёт, и при смене главы его нужно обновить в новой версии. Тот же запрос любому адресату отправляет `/chillzone link Имя Фамилия`; ответ на запрос главы подтверждается `/chillzone accept Имя Фамилия`. Имя и реальная гильдия проверяются вне запроса. Название гильдии может быть любым; `C.GUILDS` больше не используется. Состав хранится в SavedVariables, подтверждается подписью главы и передаётся через реле. Для удаления нужен второй щелчок с подтверждением. Гильдии, чей корень уже лежит в SavedVariables аккаунта главы (подключённые до `CHZUNION1` или гильдии его других персонажей той же группы реалмов и фракции), показаны на вкладке в разделе «Известные гильдии» и добавляются вторым щелчком без запроса связи. Решение дойдёт до гильдии шёпотом её корню, когда тот будет в игре одновременно с главой, или через общие SavedVariables, когда войдёт персонаж главы из этой гильдии: так один игрок с одним аккаунтом подключает свою вторую гильдию. Своим персонажам аккаунта решение не шепчется; контакту, которого нет в игре, глава не шепчет полчаса. Передача главы в игре передаёт управление без привязки к имени основателя. `/chillzone relay add` остаётся псевдонимом запроса связи и сам по себе доступа не даёт.

Обновляться с 0.8 и 0.9 можно в любом порядке. Прежние подтверждённые корни переносятся в состав автоматически; настройки чата, личные ключи и сертификаты сохраняются. Глава может обновиться последним: когда он войдёт со свежим сертификатом, аддон подпишет состав без команд и повторного добавления гильдий. Чат и сертификаты сохраняют `CHZSIGNED1`, а новые решения главы и запрос состава используют отдельный `CHZUNION1`. До первого решения главы сохраняется прежняя модель доверия офицерам; после его получения старые каталоги и корни не отменяют новое членство и исключения, в том числе после перезапуска. Необновлённые клиенты продолжают жить по прежним правилам, поэтому для применения нового состава всеми участниками нужно обновить всех. Пока глава на 0.9, его клиент молча отбрасывает запросы связи от гильдий без «Чиллзон» в названии: такой запрос истечёт через три минуты, и после обновления главы его нужно отправить заново. Гильдии с «Чиллзон» в названии он видит в чате и подтверждает прежней командой. Подробности и границы доверия — в [модели безопасности](SECURITY.md).

## Ограничения

- **Реле видит текст и может сорвать доставку**, но не может изменить исходный подписанный текст или автора. Доверенными для выдачи ролей остаются подтверждённые корневые и делегированные офицерские ключи.
- **Регистрация и отправка через реле требуют сертификата.** Самозаявление о гильдии, произвольный отчёт и прямой неподписанный шёпот доступа не дают.
- **Ранги чужих гильдий для прав чата** берутся из свежих сертификатов, а не из переписи. Подписанный рядовым отчёт не делает его главой. Статистика и отображаемый состав отчёта остаются заявлением его репортёра.
- **Уровни «Офицеры» и «Главы» не секретны.** Строки всех уровней идут по GUILD всей гильдии и через реле и репортёров; любой участник может прочитать сырые аддон-сообщения. Аддон лишь не показывает эти строки тем, у кого нет ранга, и отбрасывает строки с неподтверждённым рангом.
- **Название с «Чиллзон» не создаёт доверия.** Нужны подтверждение корня гильдии и подписанный сертификат.
- **Строки канала игры не подписаны.** Канал открыт всем, кто знает его название; посторонний может писать туда что угодно, в том числе «я глава». Гильдия такой строки — только догадка по имени автора (ростер, сертификат, отчёты, поимённый онлайн), и никаких прав строка не даёт: ни ролей, ни уровней `/cz2` и `/cz3`, ни отметки «есть аддон». Если догадки нет, у строки серое `<?>`. Игрок без аддона, сменивший гильдию, может ещё некоторое время показываться со старым тегом по отчётам переписи.
- **Канал пока не защищён.** Владельца канала аддон не выбирает: обычно им становится первый вошедший, в том числе посторонний. Его пароль, бан или мут прерывают путь через канал, но не подписанный путь. Уведомления об этом видны в журнале. Защита канала — следующий этап.
- **В канал уходит только строка от нажатия Enter.** Строка из таймера, в блокировке чата или из заранее подготовленной очереди идёт только подписанным путём.
- **Лимит сервера на канал.** Не больше 3 строк игрока за ~30 секунд. Строки сверх бюджета аддона идут только подписанным путём; без сертификата такая строка не отправляется. Не проверено, общий ли лимит на все каналы игрока и зависит ли он от флага новичка (`NEWCOMER` стоял у обоих проверявших). Если общий, игрок, много пишущий в «Торговлю», чаще будет получать `THROTTLED`, а два подряд при свободном своём бюджете аддон примет за поломку канала до перезахода.
- **Канал может сломаться незаметно.** Бан без уведомления или «призрачное» членство клиент замечает только по отсутствию эха своих строк. Пока этого не было, строки уходят в канал впустую, но подписанная копия идёт всегда. Получатель, у которого канал оглох, ничего не теряет: строки приходят подписью.
- **Фильтр брани** меняет текст строки из канала у игроков, у которых он включён. Сведение копий учитывает маску, но длину замены аддон не считает постоянной: по одной пробе она сохранилась, полагаться на это рано.
- **Не проверено:** предел участников канала и слышит ли канал игрок в блокировке сообщений.
- Зоны видны другим гильдиям только при согласии репортёра. Отправляются только числа по зонам, без имён.
- **Поимённый онлайн — заявление ответившего**, как и отчёт переписи: сервер подтверждает его имя, сертификат — гильдию, но не содержимое списка. Страницы не подписываются. Клиенты до этой версии на `OQ` не отвечают: пока в гильдии ответить некому, вместо списка видно «нет ответа».
- **Офицерская строка не проходит** без действующего сертификата роли не старше 15 минут. Если издатели недоступны, членство позволяет пересылать сообщения до истечения сертификата (7 дней), но новые роли не выдаются.
- **Корень может отсутствовать полгода.** Заранее выданный отдельный допуск офицера действует 366 дней; активный офицер по свежему ростеру продлевает короткие сертификаты участников (7 дней). Глава своей гильдии с заранее выданным допуском `leader` автоматически подписывает отзыв допуска разжалованного офицера даже без корня; отзыв расходится по связанной сети, сохраняется и передаётся новым установкам. Состав объединения подписан отдельно закреплённым ключом главы ЧЗ и действует до нового решения. Допуск издателя и право отзыва своих офицеров не дают управления составом объединения. Смена ключа управления требует подписи прежнего владельца либо явного восстановления доверия; подробности — в `SECURITY.md`.
- **Исключённый участник может писать от имени гильдии до 7 дней**, пока не истёк его сертификат. Раньше срока сертификаты отзываются только сбросом корня: своя гильдия делает `/chillzone trust reset` и новый `/chillzone trust init`, другие гильдии сбрасывают её корень у себя и повторяют `/chillzone link`.
- **Выход репортёра из игры.** Реле снимает его аренду сразу, по ответу сервера «игрок не найден». Гильдия выбирает нового репортёра, когда свежий ростер покажет прежнего вне игры: обычно в пределах минуты, в худшем случае около полутора минут вместе с регистрацией у реле. В это время строки и перепись других гильдий в эту гильдию не приходят. Клиенты читают ростер в разное время: кто прочитал позже, тот позже начинает принимать нового репортёра. Клиенты версий до 0.10.0 включительно ждут три минуты без привета H1, поэтому нового репортёра, обновившегося раньше них, принимают только после этого срока. Обычная смена репортёра, когда входит более подходящий, доставку не прерывает.
- **Молчащее реле теряет строки чата.** Персонаж реле в игре с выключенным аддоном принимает шёпот молча, и сервер об ошибке не сообщает. Отчёт переписи идёт двум реле и доходит через второе. Строка чата идёт одному: репортёр гильдии исключает молчащее реле по тайм-ауту опроса примерно через 45 секунд, а остальные её участники реле не опрашивают и могут выбирать его до 15 минут после его последнего ответа (`Config.RELAY_VERIFIED`) или до смены окна выбора (`Config.RELAY_WINDOW`). Их строки другим гильдиям в это время не доходят.
- **Отчёты в обход репортёра понимают только обновлённые клиенты.** Клиенты до этой версии берут пересылку только у репортёра: рассылку реле и ответы помощников на Q1 они отклоняют (строка «RG от ... отклонён» в их журнале) и получают отчёт, как раньше, когда его перешлёт репортёр. Помощниками они не бывают: в очередь входят только клиенты новее последней вышедшей версии без помощников. Если репортёр сам на старой версии и молчит, обновлённые получают ответ на Q1 от помощников, а старые — нет. Строки чата в обход репортёра не идут ни у кого: пока репортёр гильдии молчит, чужие строки `/cz2`, `/cz3` и подписанные копии `/cz1` в неё не приходят. Отчёт, не дошедший ни до одного реле главной гильдии, гильдии берут у его автора напрямую, но не сразу (следующий пункт).
- **Отчёт напрямую приходит не сразу и не всегда.** Запрос уходит, когда отчёт старше 12 минут, поэтому при молчащих реле отчёты других гильдий обновляются примерно раз в 12–15 минут вместо 3–10. Ответить может любой клиент новой версии из той гильдии, кроме только что вошедшего (меньше трёх минут слушает приветы) и того, кто в блокировке чата. Отчёт, подписанный ради ответа не репортёром, у спросившего вытесняет прежний и получает своё время: отчёт репортёра той гильдии со временем меньше этого, пришедший позже через реле, отклоняется как «старее» до следующего отчёта репортёра (обычно до 10 минут). Если в гильдии в игре нет никого с аддоном новой версии, отчёт не придёт, а раунды запросов будут реже, до раза в час. Если репортёр старой версии или ему не отвечают, отчёт приходит не раньше чем через 17 минут: помощник спрашивает на 5 минут позже репортёра. Отчёт, который помощник получил напрямую и отдал гильдии, клиенты до этой версии отклоняют, как любой RG не от репортёра.
- **Номер новой версии ничем не подтверждён.** Двое участников, сговорившись, могут назвать несуществующую версию и вызвать ложное предупреждение. Один игрок или одна тестовая сборка этого не делают.
- **Случайность внутри игры не имеет гарантии CSPRNG.** Используется автоматическое смешивание локальных источников по подходу Olympus; это ограничение сохранено явно.

## Проверка в игре

Что нельзя проверить без живого сервера. Чек-лист:

1. Персонаж А — текущий глава «Чиллзон», В — глава или офицер «Чиллзон Север». А и В выполняют `/chillzone trust init` в своих гильдиях; через 10 секунд `/chillzone trust` показывает корень. Повторный `/chillzone trust init` у второго офицера той же гильдии отказывает и называет корень. В выполняет `/chillzone link Имя Фамилия А`; А после внешней проверки нажимает «Добавить в объединение» на вкладке «Объединение» или отвечает `/chillzone accept Имя Фамилия В`. Б — обычный участник Севера с аддоном.
2. `/chillzone status` у всех:
   - имя показано как «Имя Фамилия»;
   - группа реалмов — `ForeverPvE` или `ForeverPvP`;
   - `splitNames=true`.
3. Б и В показывают одного репортёра, с приоритетом офицера. После выхода всех офицеров подтверждённый рядовой становится репортёром и продолжает обмен: новый репортёр виден в `/chillzone status` не позже чем через полторы минуты, и строки других гильдий снова приходят. Согласие на зоны не вытесняет доступного офицера. Если входит офицер, которого выборы ставят выше, строки других гильдий, отправленные в первые две минуты после его входа, приходят Б по одному разу; через пару минут у А среди репортёров — уже он.
4. За 3–4 минуты гильдии видят друг друга во вкладке «Перепись». Король стоит наверху «Королевства». Круги на карте есть только у согласившихся гильдий.
5. `/cz1` приходит всем по одному разу, у получателя с включённым и выключенным каналом игры. Ссылка на предмет кликабельна. `/cz2` от рядового отклоняется.
6. Чат между гильдиями идёт через реле, ссылки остаются целыми. Персонаж, который был в `ChillzoneA` со старой версии, через несколько секунд после входа из него выходит.
7. Второй участник главной гильдии Д появляется в `/chillzone relay` у Б как реле из ответа.
8. После `/reload` перепись восстанавливается по запросу у репортёра после загрузки ростера и настроек доверия. Новая установка без сохранённого доверия требует доступного офицера своей гильдии.
9. В подземелье чат блокируется. После выхода очередь уходит. Если блокировка длилась дольше 3 минут, а гильдия выбрала репортёром другого, в журнале этого персонажа нет новой строки «отчёт отправлен», а у согильдийцев нет отказов «RG от ... отклонён» с его именем.
10. Персонаж Орды видит отдельную перепись.
11. `/чз привет` и `/чз1 привет` уходят в общий чат; `/чз status` и `/chillzone status` выполняют команду, `/чз1 status` отправляет слово в чат. `/чз` без текста по Enter открывает общий канал. При наборе `/cz ` и `/cz settings` окно остаётся закрытым до Enter.
12. С `TRUST_ANY_MEMBER = false`: персонаж со званием «Ветеран» в главной гильдии в `/chillzone relay` у других гильдий виден как реле; `/chillzone status` у него пишет «связной».
13. Персонаж, чьё звание не первое, но с галочкой «Офицер» в настройках гильдии, может писать в `/cz2` и виден офицером в переписи. Персонаж со званием 1 без галочки — нет. После смены галочки это видно в течение пары минут.
14. У главы или офицера `/chillzone diag` открывает «Отладку». У Б в списке реле есть А в состоянии «отвечает», а у А среди репортёров есть гильдия Б. У рядового значка вкладки нет, а `/chillzone diag` отказывает.
15. Персонаж без гильдии и персонаж из другой гильдии через `/chillzone` видят вступление. Персонажу из другой гильдии текст называет его гильдию и объясняет подключение; кнопка «Найти гильдии» и список стоят под текстом и его не перекрывают. «Найти гильдии» открывает штатный `/who`; находятся гильдии своей фракции. Если первый поиск показал только заполненную главную гильдию, гильдия с местами из подсказки появляется в списке выше неё, а строка под кнопкой говорит, что сделает следующий щелчок. Через 10 секунд он отправляет `/who "Имя Фамилия"` её офицера или `/who g-"Её название"`, и офицер появляется в строке гильдии. У заполненной гильдии видны офицеры, а кнопка «Мест нет» неактивна. Когда гильдиям с местами больше ничего не нужно, при 50 строках следующий поиск добавляет участников из диапазона уровней. Посторонний `/who` во время поиска не попадает в список адресатов. Под названием гильдии — имена её офицеров в игре, а не число найденных; рядовых в строке нет. У гильдии, чьих офицеров не видно, кнопка «Офицеры не найдены» неактивна. Если офицер назван, но не попал в выдачу, следующий щелчок отправляет `/who "Имя Фамилия"`, и офицер появляется в строке гильдии.
16. У главы и офицеров вкладка «Заявки» видна и без заявок: значок без подписи той же ширины, что остальные вкладки, без растянутой подсветки; число заявок — в подсказке. У рядового вкладки нет, между соседними значками нет пустого места, а `/chillzone requests` отвечает отказом. Новичок отправляет редактируемую просьбу офицеру; она появляется у него и у остальных офицеров своей гильдии с именем, уровнем, классом, текстом и первым получателем. Другой офицер принимает или отклоняет её, после доставки решения она исчезает у остальных. «Закрыть для всех» не отправляет ответа новичку. Просьба, пришедшая рядовому (в том числе от старой версии без JT), появляется у офицеров, а рядовой видит в чате, что её увидят глава и офицеры. Другая гильдия и другие рядовые текст не получают. Вошедший позже офицер восстанавливает очередь; после понижения чужие заявки пропадают. Все офицеры и первоначальный адресат используют обновлённую версию. До приглашения из другой гильдии игрок выходит самостоятельно.
17. `/chillzone nocontact on` у адресата убирает его из следующего выбора и закрывает уже открытое письмо после ответа его аддона. После `/reload` настройка сохраняется. Смена гильдии и уже вступивший новичок не допускают старое приглашение. Заявка, которой несколько часов, остаётся доступной; новые заявки не вытесняют старые при количестве больше 30.
18. После поиска, редактирования письма, отправки, принятия и отказа работают `/cast`, `/target` и штатное приглашение без ошибки taint, с мышью и в режиме геймпада. При блокировке сообщений в подземелье просьба не отправляется.
19. У двух персонажей версия аддона новее, чем у третьего (у одного — в другой гильдии). Через пару минут третий видит в чате «вышла версия…» один раз, а заголовок окна Chillzone просит обновиться и не наезжает на портрет и крестик. `/chillzone status` пишет обе версии. После обновления и перезапуска игры предупреждения нет.
20. У текущего главы «Чиллзон» есть вкладка «Объединение» с управлением составом. У главы и офицера гильдии вне объединения на ней только запрос связи. У офицера «Чиллзон», рядовых и офицеров подключённых гильдий вкладки нет. Запрос связи с представителем и подтверждение добавляют гильдию с любым названием; список видят новые игроки после входа и `/reload`.
21. Первый щелчок «Удалить из объединения» просит подтверждение, второй исключает гильдию у остальных клиентов. Её можно снова добавить новым соединением или из списка известных. После передачи главы вкладка исчезает у прежнего главы и появляется у нового; действия прежнего и отложенная подпись больше не меняют состав.
22. Глава «Чиллзон» с персонажем во второй гильдии на том же аккаунте: в новой установке гильдия второго персонажа видна в разделе «Известные гильдии» и добавляется вторым щелчком. Сообщения «нет такого игрока» не появляются. После входа персонажем второй гильдии он сразу в объединении, а её участники с аддоном получают состав без участия главы. При обновлении с 0.8 и 0.9 прежние гильдии уже включены автоматически.
23. Сохранить настройки действующего объединения 0.9. Сначала обновить рядового и проверить чат в обе стороны с 0.9. Затем обновить представителя второй гильдии и офицера главной; главу обновить последним. Никаких повторных `trust init`, `link`, `accept` или щелчков добавления: после входа главы прежний состав подписывается сам. Проверить новую установку среди клиентов 0.9. После подписи главы исключить гильдию, перезайти и проверить, что старые клиенты не возвращают её в состав у обновлённых.
24. Открыть окно сразу после входа: в нижней полосе справа появляется «Читаю ростер...», затем «Запрашиваю отчёты...», точка пульсирует, а на пустой «Переписи» написано, что отчёты запрашиваются. Строка и кнопка «Обновить» стоят на нижней полосе на всех вкладках и при длинном тексте не наезжают на поле ввода чата, а «В сети: N из M» видно под списком людей, вровень с полем ввода. Нажать «Обновить»: на кнопке «Обновляю...», затем обратный отсчёт, в строке итог на несколько секунд. Подсказка отключённой кнопки видна при наведении. Персонаж без гильдии кнопки не видит, а его кнопка поиска считает секунды до следующего `/who`. Войти в бой или подземелье с запретом отправки: при непустой очереди точка красная, после снятия запрета пропадает.
25. Участник другой гильдии открывает «Перепись» и выбирает гильдию А: внизу карточки появляются все, кто в игре, включая игрока без аддона; заголовок сначала показывает запрос, затем «получено страниц» и «обновлено». Пока списка нет, внизу окна видно «Запрашиваю списки игроков», а при обновлении раз в две минуты эта строка не появляется. Небольшая гильдия приходит за несколько секунд, сто с лишним человек — примерно за 40 секунд. Строка «Все гильдии» показывает всех одной таблицей с колонкой гильдии, счётчик «в списке N из M» сходится, а над таблицей названы гильдии, чьи списки ещё идут или не пришли. Щелчок по заголовку колонки сортирует и разворачивает порядок, заголовок при прокрутке остаётся наверху. В колонке CZ значок стоит у игроков с аддоном и в своей гильдии, и в чужих, а у игрока без аддона его нет. Правый щелчок по имени открывает меню. При закрытом окне и на других вкладках шёпоты `OQ` не уходят (журнал). Репортёр в подземелье не отвечает, а через 20 секунд отвечает другой. Во время передачи большого списка чат у отвечающего не задерживается, а сервер не отказывает в отправке из-за частоты сообщений.
26. Канал игры для `/cz1`. После входа `/chillzone status` показывает `ChillzoneChatA` (у Орды `ChillzoneChatH`) с номером; номера «Общий», «Торговля» и других каналов игры не сдвинулись, сырой строки канала и уведомлений о входе в чате игры нет. `/cz1` приходит по одному разу у получателя с включённым и выключенным каналом; у отправителя растут «отправлено» и «эхо», состояние «исправен». После отправки работают `/cast` и `/target`.
27. Игрок без аддона из гильдии объединения входит в канал через `/join` и пишет туда: у участников с аддоном строка видна с тегом его гильдии. Посторонний без гильдии объединения виден с серым `<?>`, а галочка «Скрывать неподтверждённых» его строки убирает. В подземелье строка `/cz1` уходит только подписанным путём после выхода.
28. Неделю собирать счётчики путей (`/chillzone status`, «Отладка»): сколько строк пришло только каналом, только подписью и обоими, сколько своих строк вернулось эхом, сколько ушло сверх бюджета, сколько пришло подписью без копии из канала.
29. Четыре строки `/cz1` подряд за полминуты: в канал уходят три, четвёртая — только подписью и приходит всем один раз; `THROTTLED` в журнале нет. Без сертификата четвёртая не уходит, аддон называет число секунд, текст остаётся в поле окна.
30. Фильтр брани включён у получателя и у автора: строка с бранным словом видна у обоих один раз, у автора состояние канала остаётся «исправен».
31. Владелец канала банит участника (или участник выходит из канала в момент серии отклонённых строк): после двух строк без эха у него «сломан до перезахода персонажа», одна подсказка в чате, строки идут через реле, повторных входов в журнале нет. После `/reload` состояние то же, после перезахода персонажа канал снова исправен.
32. Рядовой главной гильдии, пока её репортёр в подземелье или не отвечает на шёпот: отчёты других гильдий во вкладке «Перепись» не старше нескольких минут, а в журнале (`/chillzone journal`) есть строки «отчёт ... принят от ...: он не репортёр гильдии» с именем реле. Отказов «RG от ... отклонён: он не репортёр гильдии» на отчёты у обновлённого клиента нет, остаются только отказы строкам чата. У клиента старой версии те же рассылки реле дают отказы, а отчёт приходит от репортёра.
33. Ответ на Q1 без репортёра. Репортёр главной гильдии заходит в подземелье (его ответ ждёт конца блокировки), офицер и ещё двое обновлённых согильдийцев в игре больше трёх минут. Рядовой перезаходит или нажимает «Обновить»: через минуту в «Переписи» есть отчёты других гильдий, у первого помощника (обычно офицер) в журнале строка «ответ на Q1 вместо репортёра: N из M отчётов», у остальных помощников такой строки нет или в ней меньше отчётов. После выхода репортёра из подземелья у рядового нет новых строк «отчёт ... принят от ...» с теми же гильдиями.
34. Отчёт через два реле. Одно из реле, которые «Отладка» репортёра Севера показывает отвечающими, выключает аддон и делает `/reload`, оставаясь в игре. ## Разработка

```
Chillzone/          аддон (копируется в AddOns)
Chillzone/media/    значок и логотип (TGA)
tests/              тесты: luajit tests/run.lua
reference/          Olympus 1.5.0 для справки (не в git)
.github/workflows/  CI и сборка релиза
.luacheckrc         настройки luacheck
```

Тесты и линтер запускаются так (luajit и luacheck на Windows ставятся через `scoop install luajit luacheck`):

```bash
luajit tests/run.lua
bash tests/run-parallel.sh lua5.1
luacheck Chillzone tests
```

Параллельный запуск требует Bash в Linux или WSL: по умолчанию это четыре процесса Lua 5.1. Можно выбрать интерпретатор и число процессов от 1 до 64, например `bash tests/run-parallel.sh luajit 4`. Тесты распределяются без повторов и пропусков; ошибка хотя бы одной части делает весь прогон неуспешным. Обычный `tests/run.lua` остаётся последовательным, `CZ_TEST_FILTER` работает в обоих режимах.

CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) запускает линтер, проверку запуска процессов и полный набор в четырёх процессах отдельно для Lua 5.1 и LuaJIT на каждый PR и пуш в `main`. Обязательные проверки сохраняют имена `Luacheck`, `Tests (lua5.1)` и `Tests (luajit)`.

luacheck следит за глобалами: аддон может писать только в перечисленные в `globals` из `.luacheckrc`, а читать — только Lua 5.1 и API игры из `read_globals`. Понадобилась новая функция игры — добавьте её в `read_globals`. Проверяются только `Chillzone` и `tests`, без `Chillzone/libs`: локальные копии проекта в других каталогах в прогон не попадают.

Тесты проверяют:

- синтаксис Lua 5.1, отсутствие BOM и утечек глобалов, одинаковую версию в `Chillzone.toc` и `Config.lua`, текстуры из `media/` (есть, несжатые 32-битные TGA, стороны — степени двойки);
- регистр кириллицы, правило гильдии, имена Forever;
- кодек отчётов и чата, куски, выборы;
- приём отчётов и сроки хранения;
- работу шести клиентов в симуляторе мира (`tests/wow.lua`): перепись, реле, чат, любой участник — репортёр и реле, а с проверкой по званию — подделки пересылок от рядового, выборы репортёра по званию, связной-реле; офицер по флагу звания, а без флага — по номеру звания; смена репортёра без потери строк и без перехвата аренды; выход репортёра из игры, в том числе при смешанной сети с 0.9; выход из старых каналов, выход реле, `/reload`, `/чз`; вкладка «Отладка»: кому видна и что на ней; приоритет главы и офицеров при выборе реле; реле вне общей тройки с частью репортёров и переход новой гильдии на общую тройку;

### Замер производительности

Если игроки жалуются на рывки, попросите включить запись кнопкой «Начать замер» на вкладке «Журнал» или командой `/chillzone perf`, поиграть там, где рывки заметны, остановить запись и прислать текст из «Скопировать отчёт». Запись хранится в памяти до `/reload` или выхода из игры, на диск не попадает. Загрузка при входе в неё не входит. Пока запись выключена, `ns.SafeCall` остаётся обычным, а обёртки `ns.Perf.Wrap` только проверяют флаг.

Как читать отчёт:

- **Рывки.** Рывок — кадр от 50 мс и вдвое дольше обычного. Если доля аддона редко доходит до 25% кадра, причину надо искать не в наших обработчиках.
- **Кадры с наибольшим нашим временем.** Для каждого указаны длина, наше время, главные метки, бой и открытая вкладка. Большое «освобождено» при малом «наших» указывает на сборщик мусора, общий для всех аддонов.
- **Время рывков.** Равные промежутки по 60 секунд указывают на плановое чтение ростера.
- **Метки по самому долгому вызову** ищут причину рывков, **метки по сумме времени** показывают расход CPU. У каждой метки своё время, без вложенных вызовов.

`crypto slice` — кусок проверки подписи за один кадр, `signature done` — обработка уже проверенного сообщения. Остальные метки — это аргумент `where` у `ns.SafeCall`, имена таймеров и событий (`event X`, `callback X`, `recv X`).

Замер не видит сторонние библиотеки из `libs/` и разовые обработчики нажатий. Новый постоянный `OnUpdate` нужно обернуть в `ns.Perf.Wrap`, иначе в отчёт он не попадёт.

### Выпуск версии

`main` защищена: прямой пуш отклоняется, в том числе для изменения номера версии. Ниже `X.Y.Z` — номер выпускаемой версии.

1. Создать отдельную ветку от актуальной `main`. Поднять версию в двух местах: `## Version:` в `Chillzone/Chillzone.toc` и `C.VERSION` в `Chillzone/Config.lua`. Закоммитить и открыть PR в `main`.
   Если до релиза сборку проверяют в игре несколько человек, пометьте версию хвостом в обоих местах (`X.Y.Z-test`). Иначе у их согильдийцев появится просьба обновиться до версии, которой ещё нет: предупреждению хватает двух игроков с новым номером.
2. Дождаться всех трёх обязательных проверок: `Luacheck`, `Tests (lua5.1)` и `Tests (luajit)`. Слить PR.
3. Переключиться на `main` и подтянуть результат: `git switch main`, затем `git pull --ff-only origin main`. Убедиться, что обе версии равны `X.Y.Z`. Поставить тег на этот коммит: `git tag -a vX.Y.Z -m "Chillzone: версия X.Y.Z"`, затем `git push origin vX.Y.Z`. Тег ставится после слияния PR, а не на его ветку.
4. Дождаться успешного [`.github/workflows/release.yml`](../.github/workflows/release.yml). Он заново прогонит тесты и luacheck, сверит тег с версией в toc, соберёт `Chillzone-X.Y.Z.zip` и создаст черновик релиза. Если релиз уже существует, workflow приложит архив к нему.
5. Проверить приложенный ZIP: внутри одна папка `Chillzone`, состав соответствует тегу, в `Chillzone.toc` и `Config.lua` указана выпускаемая версия, исправления вошли в архив. Заполнить «Что нового» по изменениям с предыдущего релиза, указать совместимость при изменении протокола и порядок обновления. После этого опубликовать релиз и отметить его последним: `gh release edit vX.Y.Z --draft=false --latest`.
6. Если настроен CurseForge, после публикации [`.github/workflows/curseforge.yml`](../.github/workflows/curseforge.yml) загрузит туда тот же архив, а описание релиза станет changelog. Дождаться успешного `Upload to CurseForge`; появление файла для игроков зависит ещё и от модерации CurseForge. Повторный запуск создаёт новый файл, поэтому уже загруженную версию не нужно отправлять повторно или загружать вручную через сайт.

Описание можно подготовить заранее: после отправки тега создать **черновик** командой `gh release create vX.Y.Z --draft --verify-tag --title "Chillzone X.Y.Z" --notes-file notes.md`. Workflow приложит архив к этому черновику. Если черновик уже создан workflow, обновить описание через `gh release edit vX.Y.Z --notes-file notes.md`. Публикация в обоих случаях — только после проверок и появления готового ZIP.

#### Разовая настройка CurseForge

1. Создать проект для **World of Warcraft** в [кабинете авторов](https://authors.curseforge.com/#/projects/create/choose-game), если его ещё нет. Указать название, английское описание, категорию, значок и лицензию MIT. Сохранить числовой **Project ID** проекта. Для первого одобрения CurseForge нужен загруженный файл; отправка через API не отменяет модерацию ([порядок создания проекта](https://support.curseforge.com/support/solutions/articles/9000197241-creating-and-submitting-a-project)).
2. Создать токен на странице [API Tokens](https://authors.curseforge.com/#/settings/api-tokens) в аккаунте с правом загружать файлы в этот проект. Это токен **Upload API** ([документация](https://support.curseforge.com/support/solutions/articles/9000197321-curseforge-upload-api)).
3. В GitHub открыть [Settings → Secrets and variables → Actions](https://github.com/FiNEk/Chillzone/settings/secrets/actions):
   - на вкладке **Variables** добавить repository variable `CURSEFORGE_PROJECT_ID` с числовым ID. Без неё загрузка пропускается;
   - на вкладке **Secrets** добавить repository secret `CURSEFORGE_API_TOKEN` с токеном. Его значение не нужно добавлять в код или описание PR;
   - необязательно добавить переменную `CURSEFORGE_GAME_VERSIONS` — версии игры через запятую. По умолчанию они берутся из `## Interface` в toc архива: `11509` → `1.15.9`. Неизвестные CurseForge версии пропускаются с предупреждением; если не найдена ни одна, workflow упадёт и перечислит известные Classic-версии. Ручной список задаётся только из версий, которые действительно поддерживает аддон.
4. Слить PR с `curseforge.yml` в `main`. Для первой загрузки уже опубликованного релиза открыть [Actions → CurseForge](https://github.com/FiNEk/Chillzone/actions/workflows/curseforge.yml), выбрать **Run workflow**, ветку **main**, указать тег нужного релиза (например, `v0.11.1`). Если эта версия уже загружена на CurseForge, выбрать следующую ещё не загруженную. После успешной отправки проверить файл и его статус в кабинете авторов.

Следующие релизы отправляются автоматически при публикации пользователем через сайт GitHub или `gh` с личной авторизацией. Создание черновика само по себе загрузку не запускает. Если другой workflow публикует релиз через `GITHUB_TOKEN`, событие `release: published` не запускает следующий workflow: для такого релиза нужен **Run workflow** с его тегом ([ограничение GitHub](https://docs.github.com/en/actions/concepts/security/github_token)). Этот же ручной запуск подходит для старых релизов; черновики не загружаются.
