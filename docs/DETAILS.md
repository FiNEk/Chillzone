# Chillzone — подробно

Аддон для **WoW: Forever**. Он связывает все гильдии, в названии которых есть «Чиллзон»:

- **Перепись.** Численность гильдий, сколько участников в игре, главы, офицеры, классы, уровни, неактивные.
- **Королевство.** Глава главной гильдии «Чиллзон» — Король. Главы остальных гильдий — Лорды, офицеры — Капитаны.
- **Карта.** Круги на карте мира показывают, сколько участников в каждой зоне. Зоны видны только у гильдий, чей репортёр согласился ими делиться.
- **Общий чат** с тремя уровнями:

| Команда | Канал | Кто может писать и читать |
|---|---|---|
| `/cz1` | «Чиллзон» | все участники |
| `/cz2` | «Офицеры» | главы и офицеры гильдий |
| `/cz3` | «Главы» | главы гильдий и офицеры главной гильдии |

Офицер — тот, чьё звание отмечено в настройках гильдии галочкой «Офицер» (как в ChillZoneUnion 0.6). Номер звания, его название и право приглашать роли не решают. Если игра не отдала права званий, офицерский доступ не предоставляется. Глава определяется рангом 0.

- **Окно чата** в стиле «Гильдии и сообществ». Слева — каналы: свои гильдия и офицеры плюс три общих. В центре — сообщения и поле ввода, справа — люди. Перепись, королевство и настройки — вкладки на правом краю того же окна.

Код частично портирован из [Olympus](https://github.com/dnl-gentile/olympus-addon) (MIT), подробности — в [THIRD_PARTY.md](../THIRD_PARTY.md).

## Установка

1. Скопируйте папку `Chillzone` в `World of Warcraft\_classic_era_\Interface\AddOns\` (или в папку AddOns вашего клиента Forever).
2. Перезапустите игру и включите аддон в списке.
3. Проверьте: `/cz status`.

## Команды

| Команда | Что делает |
|---|---|
| `/cz` | открыть или закрыть окно (по умолчанию — чат) |
| `/cz census`, `/cz kingdom`, `/cz settings` | окно на нужной вкладке |
| `/cz1 текст`, `/cz2 текст`, `/cz3 текст` | написать в общий чат |
| `/cz текст` | то же, что `/cz1 текст`, если текст не начинается с команды |
| `/cz1`, `/cz2`, `/cz3` без текста | окно чата на этом канале, курсор в поле ввода |
| `/чз`, `/чз1`, `/чз2`, `/чз3`, `/чиллзон` | то же на кириллице: `/чз` = `/cz`, `/чз1` = `/cz1`, `/чиллзон` = `/chillzone` |
| `/cz zones on\|off` | делиться зонами своей гильдии |
| `/cz map on\|off` | круги на карте мира |
| `/cz chat on\|off` | показывать общий чат |
| `/cz window <вкладка>` | выводить общий чат во вкладку с таким названием (пусто — основное окно) |
| `/cz ignore Имя Фамилия` | игнор в общем чате (повтор снимает) |
| `/cz history 1\|2\|3` | последние 20 строк канала |
| `/cz relay` | список ретрансляторов и их состояние |
| `/cz trust init` | офицер задаёт корень доверия своей гильдии; один раз на гильдию |
| `/cz trust` | известные корни доверия |
| `/cz link Имя Фамилия`, `/cz accept Имя Фамилия` | запросить и подтвердить первое соединение гильдий |
| `/cz trust reset Название гильдии` | отозвать доверие после утраты или компрометации ключа |
| `/cz relay ping` | проверить ретрансляторы заново |
| `/cz minimap` | спрятать или показать кнопку у миникарты |
| `/cz status` | кто я, гильдия, репортёр, реле, канал, счётчики |
| `/cz diag` | окно на вкладке «Отладка» (главы и офицеры) |
| `/cz log [N]`, `/cz debug` | журнал для отладки |

## Окно чата

Окно повторяет раскладку стандартного окна «Гильдия и сообщества». Пузырей нет, строки идут одной лентой.

**Шапка** справа вверху, как у Olympus, одна на все вкладки. Крупно — сколько всего участников во всех гильдиях «Чиллзон», мелко — сколько из них в игре, сколько гильдий и когда пришёл самый свежий отчёт. Наведение показывает счёт по каждой гильдии.

**Перепись.** Слева — список гильдий: сколько в игре из скольких и кто глава. Справа — карточка выбранной гильдии (сразу выбрана ваша): крупные числа, руководство (щелчок по имени — шёпот), полоса классов в игре, столбики уровней, зоны полосками. Классы, уровни и зоны берутся только из свежего отчёта; зоны чужой гильдии видны, только если её репортёр ими делится.

**Каналы слева:**

| Канал | Что это | Кому виден |
|---|---|---|
| «<ваша гильдия>» | обычный чат гильдии игры | всем в гильдии |
| «Офицеры гильдии» | офицерский чат гильдии игры | тем, кому игра разрешает его читать |
| «Чиллзон», «Офицеры», «Главы» | общий чат гильдий «Чиллзон» (`/cz1`–`/cz3`) | по рангу, как в таблице выше |

Под названием канала подписано, чей он: «чат гильдии» или «все гильдии». Так чат гильдии «Чиллзон» не спутать с общим каналом «Чиллзон». На канале с новыми строками стоит значок и число непрочитанных. В строках общих каналов после имени серым написана гильдия автора.

**Люди справа.** Для чата своей гильдии — кто в игре; для офицерского — офицеры. Для общих каналов — главы и офицеры всех гильдий из переписи плюс все, кто писал в канал за последний час. Список сгруппирован по гильдиям. Кто не в игре, показан серым. Щелчок по имени — шёпот. Под списком — «В сети: X из Y»: в чате гильдии — по ростеру гильдии, в остальных каналах — сколько людей списка в игре.

**Поле ввода:**

- Enter отправляет строку, курсор остаётся в поле. Пустой Enter или Esc убирают курсор.
- Tab и Shift+Tab переключают канал. Стрелки ↑ и ↓ листают 20 последних отправленных строк.
- Черновик у каждого канала свой.
- `/w Имя Фамилия текст` — шёпот. Другие команды здесь не работают: их пишут в обычном чате игры.
- Shift-клик по предмету в сумке или по ссылке в окне вставляет ссылку в поле.

**Enter, пока окно открыто,** ставит курсор в поле окна, а не в чат игры. Чтобы написать в чат игры, закройте окно или нажмите `/`. В бою привязка Enter не меняется до конца боя. В режиме геймпада Enter не перехватывается.

**Строки в чате игры.** Строки общих каналов по-прежнему дублируются в обычный чат игры. Метка `[Чиллзон]` в начале строки кликабельна: щелчок открывает окно на этом канале. Дубль выключается в настройках: тогда строки видны только в окне.

**Настройки** (вкладка с шестерёнкой): общий чат вкл/выкл, дубль в чат игры, время у строк, круги на карте, делиться зонами, кнопка у миникарты.

**Отладка** (последняя вкладка, только у глав и офицеров). Обновляется раз в 5 секунд. На ней видно:

- я: ключ имени, версия, гильдия и звание; офицер ли я и откуда это известно — по флагу звания; если игра не отдала права, это указано отдельно и офицерский доступ не предоставляется; уровень в чате и роль в связи;
- реле: реле ли я и через кого уходят мои сообщения; счётчики пересылок; сколько сообщений ждёт реле; когда я как репортёр регистрировался у реле. Дальше — все известные реле: состояние («отвечает», «ждём ответа», «не в игре» и сколько ещё), «в приоритете» у главы и офицеров главной гильдии, почему я им доверяю (я сам, глава или офицер главной гильдии, участник главной гильдии). Подсказка у реле — когда отвечало, когда спрашивали, от кого я о нём узнал. Если я реле — какие репортёры гильдий у меня зарегистрированы и не устарела ли регистрация;
- перепись моей гильдии: кто репортёр; согильдийцы с аддоном, их версия (чужая — красным), делятся ли зонами, реле ли они, когда последний раз отзывались;
- отчёты гильдий: от кого пришёл последний отчёт и когда, «!» при расхождении руководства, сколько отчётов отклонено и почему;
- счётчики сообщений аддона и чата, очередь отправки;
- последние ошибки аддона (полный текст — в подсказке и в `/cz log`).

## Как это работает

На WoW: Forever сообщения аддонов в пользовательском канале **не доставляются**. Доставляются три вида сообщений:

- аддон-сообщения внутри гильдии (GUILD);
- аддон-шёпот (WHISPER). Шептать нужно на «Имя Фамилия» без реалма;
- обычный текст в канале. Аддон им не пользуется: пользовательский канал может открыть `/join` любой, кто знает название, и писать туда от имени любой гильдии.

Отсюда схема:

1. **Внутри гильдии** клиенты с аддоном раз в минуту здороваются по GUILD. Репортёр выбирается сначала среди доступных глав и офицеров, затем среди остальных подходящих участников. Внутри этой группы сохраняются выбор по имени и предпочтение согласившихся делиться зонами (`/cz zones on`).
2. **Репортёр** раз в ~3 минуты отправляет отчёт о гильдии **ретранслятору** шёпотом. Если ничего не изменилось, отчёт уходит не чаще раза в 10 минут.
3. **Ретранслятор** пересылает подписанный отчёт репортёрам остальных гильдий. Репортёр обновляет регистрацию каждые 15 секунд не более чем у трёх кандидатов. Сертификат должен подтверждать именно его имя и гильдию; аренда без обновления истекает за 60 секунд. При смене репортёра прежний ещё две минуты пересылает гильдии то, что ему шлют реле, и называет им преемника (`RU`), а реле передают аренду ему.
4. **Репортёр** раздаёт исходные подписанные пакеты своей гильдии по GUILD. Пересылка принимается от выбранного репортёра (при смене — и от прежнего), а подпись автора независимо проверяется каждым получателем.
5. **Строка чата** подписывается автором один раз и уходит по GUILD своей гильдии и через реле остальным. Подтверждать её у автора личным шёпотом не нужно. Повторы отбрасываются. Скрытые каналы старых версий больше не используются.

Свою гильдию каждый клиент видит только по своему ростеру. Чужие отчёты о ней игнорируются.

### Кто ретранслятор

- Подтверждённый сертификатом участник главной гильдии «Чиллзон» с аддоном; при ограничении по званию — глава, офицер или связной.
- Имена из ответов реле являются подсказками для поиска. Они не создают доверие без сертификата.
- Ручные разрешения и неподтверждённые отчёты не дают доступа в протоколе 0.4; список `RELAYS` в `Config.lua` убран.

Все клиенты одинаково упорядочивают реле: **сначала главы и офицеры главной гильдии** по свежему сертификату, затем остальные, внутри — по имени. Репортёры регистрируются у трёх доступных реле сверху списка, сообщения уходят через отвечающее реле из этой тройки, офицеры первыми. Если офицеры не отвечают, выбирается рядовой. Внутри выбранной группы сохраняется распределение по хешу гильдии и времени. Участник главной гильдии рассылает сам, только если у него зарегистрированы репортёры других гильдий; иначе отправляет реле из тройки, как все. Конфликт неподтверждённых отчётов не меняет права. Постоянный опрос выполняют репортёры; обычный читатель не опрашивает весь союз.

### Проверка по званию (сейчас выключена)

Пока звания не розданы, `TRUST_ANY_MEMBER = true`: репортёром и реле может быть любой участник. Чтобы вернуть проверку, поставьте `false` в `Chillzone/Config.lua`. Тогда:

- репортёр гильдии — только её глава, офицер или связной; если никого из них нет в игре, репортёра нет, и перепись и строки других гильдий ждут;
- реле — только глава, офицеры и связные главной гильдии;
- пересылки по GUILD по-прежнему требуют выбранного репортёра и верной подписи; настройка не отключает проверку авторства.

Связной — персонаж со званием `RELAY_RANK` (по умолчанию «Ветеран»), которое сравнивается целиком без учёта регистра и пробелов по краям. Смена звания учитывается по свежему ростеру и новому сертификату; извне отзыв узнаётся после обновления. Связной не получает офицерских прав или права выдавать сертификаты, но видит пересылаемый текст.

## Настройка

Всё, что настраивает автор, лежит в `Chillzone/Config.lua`:

```lua
C.GUILD_TOKEN = "Чиллзон"  -- подстрока в названии «своей» гильдии (без учёта регистра)
C.MAIN_GUILD = "Чиллзон"   -- главная гильдия
C.OFFICER_RANK = 1         -- значение для чистых сборщиков данных, не запасной допуск
C.RELAY_RANK = "Ветеран"   -- звание связных ("" — только глава и офицеры)
C.TRUST_ANY_MEMBER = true  -- репортёр и реле — любой участник; false — по званию
C.GUILDS = {}              -- необязательный белый список гильдий
```

**Корень доверия задаёт офицер.** В каждой гильдии один раз офицер выполняет `/cz trust init`: его ключ становится корнем, остальные офицеры получают корень сами. Аддон сначала 10 секунд спрашивает гильдию и не создаёт второй корень, если он уже есть. Без корня сертификаты не выдаются, и гильдия в обмене не участвует.

**Первое соединение подтверждают офицеры.** Офицер подключаемой гильдии выполняет `/cz link Имя Фамилия`, указывая известного офицера главной гильдии. Тот проверяет имя и гильдию вне запроса и подтверждает `/cz accept Имя Фамилия`. Ключи создаются автоматически и сохраняются; прописывать персонажей в коде не нужно. `/cz relay add` оставлен как совместимый псевдоним запроса соединения и сам по себе доверия не выдаёт.

При обновлении на 0.4 обновиться должны все стороны. Старый протокол не принимается; настройки чата сохраняются, неподтверждённое доверие сбрасывается. Подробности — в [модели безопасности](SECURITY.md).

## Ограничения

- **Реле видит текст и может сорвать доставку**, но не может изменить исходный подписанный текст или автора. Доверенными для выдачи ролей остаются подтверждённые корневые и делегированные офицерские ключи.
- **Регистрация и отправка через реле требуют сертификата.** Самозаявление о гильдии, произвольный отчёт и прямой неподписанный шёпот доступа не дают.
- **Ранги чужих гильдий для прав чата** берутся из свежих сертификатов, а не из переписи. Подписанный рядовым отчёт не делает его главой. Статистика и отображаемый состав отчёта остаются заявлением его репортёра.
- **Уровни «Офицеры» и «Главы» не секретны.** Строки всех уровней идут по GUILD всей гильдии и через реле и репортёров; любой участник может прочитать сырые аддон-сообщения. Аддон лишь не показывает эти строки тем, у кого нет ранга, и отбрасывает строки с неподтверждённым рангом.
- **Название с «Чиллзон» не создаёт доверия.** Нужны подтверждение корня гильдии и подписанный сертификат.
- Зоны видны другим гильдиям только при согласии репортёра. Отправляются только числа по зонам, без имён.
- **Офицерская строка не проходит** без действующего сертификата роли не старше 15 минут. Если издатели недоступны, членство позволяет пересылать сообщения до истечения сертификата (7 дней), но новые роли не выдаются.
- **Корневой офицер должен заходить хотя бы раз в неделю.** Делегирования остальных офицеров продлевает только он. Через 7 дней после его последнего входа выдавать сертификаты некому, и они у гильдии истекают.
- **Исключённый участник может писать от имени гильдии до 7 дней**, пока не истёк его сертификат. Раньше срока сертификаты отзываются только сбросом корня: своя гильдия делает `/cz trust reset` и новый `/cz trust init`, другие гильдии сбрасывают её корень у себя и повторяют `/cz link`.
- **Выход репортёра из игры.** Реле снимает его аренду сразу, по ответу сервера «игрок не найден», но гильдия выбирает нового репортёра, только когда прежний пропадёт из выборов (до трёх минут без его привета H1). Всё это время строки и перепись других гильдий в эту гильдию не приходят. Обычная смена репортёра, когда входит более подходящий, доставку не прерывает.
- **Случайность внутри игры не имеет гарантии CSPRNG.** Используется автоматическое смешивание локальных источников по подходу Olympus; это ограничение сохранено явно.

## Проверка в игре

Что нельзя проверить без живого сервера. Чек-лист:

1. Персонаж А — офицер «Чиллзон», В — глава или офицер «Чиллзон Север». А и В выполняют `/cz trust init` в своих гильдиях; через 10 секунд `/cz trust` показывает корень. Повторный `/cz trust init` у второго офицера той же гильдии отказывает и называет корень. В выполняет `/cz link Имя Фамилия А`; А после внешней проверки отвечает `/cz accept Имя Фамилия В`. Б — обычный участник Севера с аддоном.
2. `/cz status` у всех:
   - имя показано как «Имя Фамилия»;
   - группа реалмов — `ForeverPvE` или `ForeverPvP`;
   - `splitNames=true`.
3. Б и В показывают одного репортёра, с приоритетом офицера. После выхода всех офицеров подтверждённый рядовой становится репортёром и продолжает обмен. Согласие на зоны не вытесняет доступного офицера. Если входит офицер, которого выборы ставят выше, строки других гильдий, отправленные в первые две минуты после его входа, приходят Б по одному разу; через пару минут у А среди репортёров — уже он.
4. За 3–4 минуты гильдии видят друг друга во вкладке «Перепись». Король стоит наверху «Королевства». Круги на карте есть только у согласившихся гильдий.
5. `/cz1` приходит всем по одному разу. Ссылка на предмет кликабельна. `/cz2` от рядового отклоняется.
6. Чат между гильдиями идёт через реле, ссылки остаются целыми. Персонаж, который был в `ChillzoneA` со старой версии, через несколько секунд после входа из него выходит.
7. Второй участник главной гильдии Д появляется в `/cz relay` у Б как реле из ответа.
8. После `/reload` перепись восстанавливается по запросу у репортёра после загрузки ростера и настроек доверия. Новая установка без сохранённого доверия требует доступного офицера своей гильдии.
9. В подземелье чат блокируется. После выхода очередь уходит.
10. Персонаж Орды видит отдельную перепись.
11. `/чз привет` и `/чз1 привет` уходят в общий чат, `/чз status` выполняет команду, `/чз` без текста открывает окно.
12. С `TRUST_ANY_MEMBER = false`: персонаж со званием «Ветеран» в главной гильдии в `/cz relay` у других гильдий виден как реле; `/cz status` у него пишет «связной».
13. Персонаж, чьё звание не первое, но с галочкой «Офицер» в настройках гильдии, может писать в `/cz2` и виден офицером в переписи. Персонаж со званием 1 без галочки — нет. После смены галочки это видно в течение пары минут.
14. У главы или офицера `/cz diag` открывает «Отладку». У Б в списке реле есть А в состоянии «отвечает», а у А среди репортёров есть гильдия Б. У рядового значка вкладки нет, а `/cz diag` отказывает.

Ещё стоит проверить в игре:

- отдаёт ли `C_GuildInfo.GuildControlGetRankFlags` права званий рядовому участнику, а не только тем, кто может менять звания. Если нет — офицером считается звание с номером не больше `OFFICER_RANK` (глава и звание 1);

- проходят ли две отправки (GUILD и шёпот реле) за одну слэш-команду;
- отдаёт ли игра название звания в `GetGuildRosterInfo` и `GetGuildInfo` так, как оно написано в настройках гильдии;
- русский текст системной строки «игрок не найден»;
- совпадают ли названия зон в ростере с картой;
- работает ли карта в режиме геймпада.

Окно чата:

- окно похоже на «Гильдию и сообщества»: нет зелёных квадратов вместо текстур и значков на вкладках и в списке каналов;
- пока окно открыто, Enter ставит курсор в поле окна; после закрытия Enter снова открывает чат игры;
- после отправки строки из окна в обычном чате работают `/cast` и `/target` (нет taint). То же — после боя;
- клик по метке `[Чиллзон]` в чате игры открывает окно на нужном канале;
- подсказки при наведении на ссылки в окне; Shift-клик по ссылке и по предмету в сумке вставляет её в поле;
- чат гильдии и офицерский чат работают в обе стороны и совпадают с чатом игры;
- щелчок по имени — шёпот, `/w Имя Фамилия текст` доходит;
- «Отладка»: длинные строки не наезжают на текст справа, значок вкладки не пустой;
- в режиме геймпада окно работает, Enter не перехватывается.
- «Перепись»: в карточке гильдии крупные числа, полоса классов, столбики уровней и полоски зон не наезжают друг на друга; щелчок по гильдии в списке меняет карточку.

## Разработка

```
Chillzone/          аддон (копируется в AddOns)
tests/              тесты: luajit tests/run.lua
reference/          Olympus 1.5.0 для справки (не в git)
.github/workflows/  CI и сборка релиза
.luacheckrc         настройки luacheck
```

Тесты и линтер запускаются так (luajit и luacheck на Windows ставятся через `scoop install luajit luacheck`):

```bash
luajit tests/run.lua
luacheck .
```

CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) запускает и то и другое на каждый PR и пуш в `main`.

luacheck следит за глобалами: аддон может писать только в перечисленные в `globals` из `.luacheckrc`, а читать — только Lua 5.1 и API игры из `read_globals`. Понадобилась новая функция игры — добавьте её в `read_globals`. Папка `Chillzone/libs` не проверяется.

Тесты проверяют:

- синтаксис Lua 5.1, отсутствие BOM и утечек глобалов, одинаковую версию в `Chillzone.toc` и `Config.lua`;
- регистр кириллицы, правило гильдии, имена Forever;
- кодек отчётов и чата, куски, выборы;
- приём отчётов и сроки хранения;
- работу шести клиентов в симуляторе мира (`tests/wow.lua`): перепись, реле, чат, любой участник — репортёр и реле, а с проверкой по званию — подделки пересылок от рядового, выборы репортёра по званию, связной-реле; офицер по флагу звания, а без флага — по номеру звания; смена репортёра без потери строк и без перехвата аренды; выход из старых каналов, выход реле, `/reload`, `/чз`; вкладка «Отладка»: кому видна и что на ней; приоритет главы и офицеров при выборе реле;
- окно чата: каналы по рангу, отправка из поля ввода, чат гильдии и офицеров, шёпот, метка-ссылка, непрочитанные, люди справа, привязка Enter в бою и вне боя.

Код выхода ненулевой, если хоть один тест упал.

### Выпуск версии

1. Поднять версию в двух местах: `## Version:` в `Chillzone/Chillzone.toc` и `C.VERSION` в `Chillzone/Config.lua`. Закоммитить в `main`.
2. Поставить тег и запушить его: `git tag v0.4.1 && git push origin v0.4.1`.
3. [`.github/workflows/release.yml`](../.github/workflows/release.yml) проверит, что тег совпадает с версией в toc, прогонит тесты и luacheck, соберёт `Chillzone-0.4.1.zip` (в нём одна папка `Chillzone`) и создаст черновик релиза с шаблоном описания.
4. Дописать в черновике «Что нового» и опубликовать.
5. После публикации [`.github/workflows/curseforge.yml`](../.github/workflows/curseforge.yml) загрузит тот же архив на CurseForge, а описание релиза станет changelog. Вручную туда ничего загружать не нужно, иначе на CurseForge будет два одинаковых файла.

Можно и наоборот: сначала `gh release create v0.4.1 --notes-file notes.md` с готовым описанием — тогда workflow приложит архив к уже созданному релизу.

Для загрузки на CurseForge в настройках репозитория (Settings → Secrets and variables → Actions) нужны:

- переменная `CURSEFORGE_PROJECT_ID` — Project ID со страницы проекта на CurseForge. Без неё загрузка пропускается;
- секрет `CURSEFORGE_API_TOKEN` — токен со страницы [API Tokens](https://authors.curseforge.com/#/settings/api-tokens);
- необязательная переменная `CURSEFORGE_GAME_VERSIONS` — версии игры через запятую (`1.15.8,2.5.5`). По умолчанию они берутся из `## Interface` в toc: `11509` → `1.15.9`. Если CurseForge не знает ни одной из них, workflow упадёт и перечислит версии, которые знает.

Уже опубликованный релиз загружается вручную: Actions → CurseForge → Run workflow, указать тег.
