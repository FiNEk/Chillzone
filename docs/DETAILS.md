# Chillzone — подробно

Аддон для **WoW: Forever**. Он связывает все гильдии, в названии которых есть «Чиллзон»:

- **Перепись.** Численность гильдий, сколько участников в игре, главы, офицеры, классы, уровни, неактивные.
- **Королевство.** Глава главной гильдии «Чиллзон» — Король. Главы остальных гильдий — Лорды, офицеры — Капитаны.
- **Карта.** Круги на карте мира показывают, сколько участников в каждой зоне. Зоны видны только у гильдий, чей репортёр согласился ими делиться.
- **Общий чат** с тремя уровнями:

| Команда | Канал | Кто может писать и читать |
|---|---|---|
| `/cz1` | «Чиллзон» | все участники |
| `/cz2` | «Офицеры» | главы и офицеры гильдий |
| `/cz3` | «Главы» | главы гильдий и офицеры главной гильдии |

Офицер — тот, чьё звание отмечено в настройках гильдии галочкой «Офицер» (как в ChillZoneUnion 0.6). Номер звания, его название и право приглашать роли не решают. Если игра не отдала права званий, офицерский доступ не предоставляется. Глава определяется рангом 0.

- **Окно чата** в стиле «Гильдии и сообществ». Слева — каналы: свои гильдия и офицеры плюс три общих. В центре — сообщения и поле ввода, справа — люди. Перепись, королевство и настройки — вкладки на правом краю того же окна.

Код частично портирован из [Olympus](https://github.com/dnl-gentile/olympus-addon) (MIT), подробности — в [THIRD_PARTY.md](../THIRD_PARTY.md).

## Установка

1. Скопируйте папку `Chillzone` в `World of Warcraft\_classic_era_\Interface\AddOns\` (или в папку AddOns вашего клиента Forever).
2. Перезапустите игру и включите аддон в списке.
3. Проверьте: `/chillzone status`.

## Команды

| Команда | Что делает |
|---|---|
| `/chillzone` | открыть или закрыть окно (по умолчанию — чат) |
| `/chillzone census`, `/chillzone kingdom`, `/chillzone settings` | окно на нужной вкладке |
| `/cz`, `/cz1`, `/cz2`, `/cz3` + пробел | переключить ввод на этот канал в окне Chillzone |
| `/cz1 текст`, `/cz2 текст`, `/cz3 текст` | написать в общий чат |
| `/cz текст` | то же, что `/cz1 текст`, включая слова команд |
| `/cz`, `/cz1`, `/cz2`, `/cz3` без текста | окно чата на этом канале, курсор в поле ввода |
| `/чз`, `/чз1`, `/чз2`, `/чз3`, `/чиллзон` | то же на кириллице: `/чз` = `/cz`, `/чз1` = `/cz1`, `/чиллзон` = `/cz` |
| `/chillzone zones on\|off` | делиться зонами своей гильдии |
| `/chillzone map on\|off` | круги на карте мира |
| `/chillzone chat on\|off` | показывать общий чат |
| `/chillzone window <вкладка>` | выводить общий чат во вкладку с таким названием (пусто — основное окно) |
| `/chillzone ignore Имя Фамилия` | игнор в общем чате (повтор снимает) |
| `/chillzone history 1\|2\|3` | последние 20 строк канала |
| `/chillzone relay` | список ретрансляторов и их состояние |
| `/chillzone trust init` | офицер задаёт корень доверия своей гильдии; один раз на гильдию |
| `/chillzone trust` | известные корни доверия |
| `/chillzone link Имя Фамилия`, `/chillzone accept Имя Фамилия` | запросить и подтвердить первое соединение гильдий |
| `/chillzone trust reset Название гильдии` | отозвать доверие после утраты или компрометации ключа |
| `/chillzone relay ping` | проверить ретрансляторы заново |
| `/chillzone minimap` | спрятать или показать кнопку у миникарты |
| `/chillzone status` | кто я, гильдия, репортёр, реле, канал, счётчики |
| `/chillzone diag` | окно на вкладке «Отладка» (главы и офицеры) |
| `/chillzone log [N]`, `/chillzone debug` | журнал для отладки |
| `/chillzone bug` | отчёт об ошибке в окне копирования (всем; то же — кнопка в «Настройках») |
| `/chillzone perf on\|off\|reset`, `/chillzone perf` | профайлер и его отчёт |
| `/chillzone acts [N\|copy]` | журнал действий доверия этого клиента |

Пробел после короткого алиаса открывает канал и переводит курсор в поле Chillzone.
Вставленный вместе с алиасом текст, включая ссылки, дописывается в черновик без отправки.
В режиме геймпада переключение по пробелу не перехватывает ввод.
Управление всегда начинается с `/chillzone`: `/cz settings` и `/чз status` — текст общего чата.

## Заявки на вступление

У персонажа вне гильдий Чиллзона `/chillzone` открывает экран вступления. Поиск через штатный `/who` находит участников своей фракции и группы реалмов, группирует их по гильдиям. Один запрос — из одного щелчка, не чаще раза в 10 секунд. Если сервер вернул 50 строк, следующие щелчки проверяют диапазоны уровней и объединяют результаты без дублей. Через 15 минут поиск начинается заново. После тайм-аута или отмены поиска чужим `/who` выдерживается ещё 30 секунд на запоздалый ответ. Открывается обычный список `/who`: аддон не меняет обработчики и события окон игры.

Один найденный участник получает J1 — запрос подсказки маршрута. J2 возвращает флаг «не беспокоить», число свободных мест и до двух контактов на гильдию. Своя гильдия берётся из ростера; чужие — из свежей подписанной переписи без конфликта, а руководство чужой гильдии дополнительно сверяется с сертификатами. Подсказка лишь сортирует гильдии и отдаёт приоритет офицерам: писать можно только тому, кого сервер действительно нашёл в этой гильдии. Король не предлагается в подсказке как контакт, но участник, найденный `/who`, остаётся запасным адресатом.

Нажатие «Попросить приглашение» открывает собственное окно аддона с редактируемым текстом и ещё раз запрашивает настройки адресата. Ответ «не беспокоить» закрывает уже открытое письмо. Отправка — один обычный шёпот и J3 с гильдией, уровнем и классом тому же игроку. Между просьбами — 20 секунд; повторно тому же адресату в этой сессии не пишем. Ответы выделены на экране вступления. Участник со старым аддоном получает только обычный шёпот.

На стороне получателя заявки показаны над карточкой «Переписи». Право «Пригласить» определяется `CanGuildInvite`, отдельно от офицерского доступа к общему чату. Приглашение — только из щелчка штатным `C_GuildInfo.Invite` или `GuildInvite`. «Отклонить» отправляет один шёпот от имени получателя, рядовой может направить к офицеру в игре, «Скрыть» ничего не отправляет. Перед действием ещё раз проверяются сама заявка, гильдия, свежий ростер и членство новичка.

Количество заявок и время до их обработки не ограничены. Показываются 5 последних; после их обработки появляются следующие. Новые заявки не вытесняют старые, а возраст заявки сам по себе не отменяет её. Заявки уже вступивших игроков удаляются при обновлении ростера. Повтор от одного из 128 последних отправителей отклоняется в течение 10 минут; уведомления в чат — не больше 6 за минуту. Выход, `/reload` и смена гильдии очищают очередь. Настройка «Принимать обращения о вступлении» и `/chillzone nocontact on|off` сохраняются для аккаунта, как в Olympus.

J1/J2/J3 принимаются только напрямую по WHISPER. Они не подписаны и не дают доступа к переписи, реле или общему чату: это просьбы новичков, а не подтверждение личности, членства или ранга. Текст обычного шёпота и метаданные могут прийти в любом порядке. Существующие подписанные форматы и префикс не меняются; старые клиенты игнорируют новые типы. Системы королевских ворот и публичных хартий Olympus в Чиллзоне нет, поэтому дополнительных приоритетов от них здесь нет.

## Окно чата

Окно повторяет раскладку стандартного окна «Гильдия и сообщества». Пузырей нет, строки идут одной лентой.

**Шапка** справа вверху, как у Olympus, одна на все вкладки. Крупно — сколько всего участников во всех гильдиях «Чиллзон», мелко — сколько из них в игре, сколько гильдий и когда пришёл самый свежий отчёт. Наведение показывает счёт по каждой гильдии.

**Перепись.** Слева — список гильдий: сколько в игре из скольких и кто глава. Справа — карточка выбранной гильдии (сразу выбрана ваша): крупные числа, руководство (щелчок по имени — шёпот), полоса классов в игре, столбики уровней, зоны полосками. Классы, уровни и зоны берутся только из свежего отчёта; зоны чужой гильдии видны, только если её репортёр ими делится.

**Каналы слева:**

| Канал | Что это | Кому виден |
|---|---|---|
| «<ваша гильдия>» | обычный чат гильдии игры | всем в гильдии |
| «Офицеры гильдии» | офицерский чат гильдии игры | тем, кому игра разрешает его читать |
| «Чиллзон», «Офицеры», «Главы» | общий чат гильдий «Чиллзон» (`/cz1`–`/cz3`) | по рангу, как в таблице выше |

Под названием канала подписано, чей он: «чат гильдии» или «все гильдии». Так чат гильдии «Чиллзон» не спутать с общим каналом «Чиллзон». На канале с новыми строками стоит значок и число непрочитанных. В строках общих каналов после имени серым написана гильдия автора.

**Люди справа.** Для чата своей гильдии — кто в игре; для офицерского — офицеры. Для общих каналов — главы и офицеры всех гильдий из переписи плюс все, кто писал в канал за последний час. Список сгруппирован по гильдиям. Кто не в игре, показан серым. Щелчок по имени — шёпот. Под списком — «В сети: X из Y»: в чате гильдии — по ростеру гильдии, в остальных каналах — сколько людей списка в игре.

**Поле ввода:**

- Enter отправляет строку, курсор остаётся в поле. Пустой Enter или Esc убирают курсор.
- Tab и Shift+Tab переключают канал. Стрелки ↑ и ↓ листают 20 последних отправленных строк.
- Черновик у каждого канала свой.
- `/w Имя Фамилия текст` — шёпот. Другие команды здесь не работают: их пишут в обычном чате игры.
- Shift-клик по предмету в сумке или по ссылке в окне вставляет ссылку в поле.

**Enter, пока окно открыто,** ставит курсор в поле окна, а не в чат игры. Чтобы написать в чат игры, закройте окно или нажмите `/`. В бою привязка Enter не меняется до конца боя. В режиме геймпада Enter не перехватывается.

**Строки в чате игры.** Строки общих каналов по-прежнему дублируются в обычный чат игры. Метка `[Чиллзон]` в начале строки кликабельна: щелчок открывает окно на этом канале. Дубль выключается в настройках: тогда строки видны только в окне.

**Согильдийцы без аддона.** Автор сообщения общего канала (`/cz` или `/cz1`, в том числе из окна Chillzone) после подписи отправляет читаемую копию `[Чиллзон] текст` в обычный `/g` своей гильдии. Chillzone с этим обновлением скрывает копию и в игровом чате, и в истории чата гильдии: остаётся одна строка общего канала. Это не зависит от порядка доставки обычного и аддонного сообщений; выключенный общий чат и игнор тоже сохраняются. В старых версиях аддона копия будет видна до обновления. Сообщения `/cz2` и `/cz3`, а также принятые сообщения других авторов в `/g` не копируются. Для этой копии метка `[Чиллзон] ` в начале обычной строки гильдии зарезервирована.

**Настройки** (вкладка с шестерёнкой): общий чат вкл/выкл, дубль в чат игры, время у строк, круги на карте, делиться зонами, кнопка у миникарты, кнопка «Отчёт об ошибке».

**Отладка** (последняя вкладка, только у глав и офицеров; автору аддона видна всегда). Обновляется раз в 5 секунд. На ней видно:

- я: ключ имени, версия, гильдия и звание; офицер ли я и откуда это известно — по флагу звания; если игра не отдала права, это указано отдельно и офицерский доступ не предоставляется; уровень в чате и роль в связи;
- реле: реле ли я и через кого уходят мои сообщения; счётчики пересылок; сколько сообщений ждёт реле; когда я как репортёр регистрировался у реле. Дальше — все известные реле: состояние («отвечает», «ждём ответа», «не в игре» и сколько ещё), «в приоритете» у главы и офицеров главной гильдии, почему я им доверяю (я сам, глава или офицер главной гильдии, участник главной гильдии). Подсказка у реле — когда отвечало, когда спрашивали, от кого я о нём узнал. Если я реле — какие репортёры гильдий у меня зарегистрированы и не устарела ли регистрация;
- перепись моей гильдии: кто репортёр; согильдийцы с аддоном, их версия (чужая — красным), делятся ли зонами, реле ли они, когда последний раз отзывались;
- отчёты гильдий: от кого пришёл последний отчёт и когда, «!» при расхождении руководства, сколько отчётов отклонено и почему;
- счётчики сообщений аддона и чата, очередь отправки;
- последние ошибки аддона со счётчиком повторов (подсказка — когда и стек, щелчок — в окно копирования), блокировки игрой, строка «Отчёт об ошибке для автора»;
- журнал действий доверия: последние 10 записей, щелчок по «весь журнал» открывает его целиком;
- только у автора аддона: «Просмотр как» и принятые отчёты об ошибках.

## Диагностика

- **Ошибки.** Обработчики событий, таймеры, команды и щелчки идут через `ns.SafeCall`. Ошибка записывается в `ChillzoneDB.errors` как `{ where, msg, stack, count, first, last, version }`. Одинаковые (место и текст) складываются в одну запись со счётчиком; записей не больше 50, стек — до 12 строк (`debugstack` в игре). Записи-строки прежних версий переводятся в такие таблицы при загрузке. Игроку один раз за сессию пишется «внутренняя ошибка». `/chillzone log` показывает журнал и три последние ошибки.
- **Блокировки игрой.** `ADDON_ACTION_BLOCKED` и `ADDON_ACTION_FORBIDDEN` про Chillzone записываются в `ChillzoneDB.blocked` (до 10, со стеком и счётчиком), про чужие аддоны — только строкой журнала. Обработчик ошибок игры (`seterrorhandler`) аддон не трогает.
- **Отчёт об ошибке.** `/chillzone bug` и кнопка «Отчёт об ошибке» в «Настройках» доступны всем. Отчёт открывается в окне копирования: версия, `GetBuildInfo`, `GetLocale`, имя, реалм, группа, `splitNames`, фракция, гильдия, звание, офицерство и откуда оно известно, уровень чата, роль в связи, реле и репортёр, счётчики, строки `/chillzone status`, ошибки со стеком, блокировки и 25 последних строк журнала. Отдельно — пробы API: что `C_GuildInfo.GuildControlGetRankFlags` отдаёт для моего звания, звание по `GetGuildInfo` и по ростеру, `UnitFullName`, `GetServerTime() - time()`, зоны ростера без uiMapID, режим геймпада. Ключей, сертификатов, корней доверия (`ns.store.security`, `ChillzoneDB.securityKeys`) и журнала действий доверия в отчёте нет; свой секрет, свои открытые ключи и любые строки base64 от 32 знаков вычищаются из текста.
- **Окно копирования.** Своё многострочное поле только для чтения. Клавиатуру оно не берёт, пока по нему не щёлкнуть; «Выделить всё», затем Ctrl+C. Escape отпускает поле, второй Escape закрывает окно. Поле ввода чата игры не трогается.
- **Профайлер.** `/chillzone perf on` подменяет `ns.SafeCall` обёрткой с замером по `debugprofilestop` и остаётся включённым после `/reload`. `off` возвращает прежний `ns.SafeCall`, `reset` стирает замеры. Без аргумента — отчёт: по метке число вызовов, сумма, самый долгий и среднее; 20 самых долгих вызовов; 10 худших кадров, где аддон занял от 20 мс. Время вызова включает вложенные, своя работа профайлера вычтена. Проверка подписей Ed25519 идёт мимо `ns.SafeCall` и меряется отдельной строкой «ed25519» (через публичное поле `Ed.after`). Ввода игрока в метках нет: у команды остаётся только её имя, хвост после «|» отрезается, числа от двух цифр заменяются на «#». Выключенный профайлер ничего не стоит и ничего не сохраняет.
- **Журнал действий доверия.** `/chillzone acts [N|copy]` и раздел на «Отладке». Только то, что увидел этот клиент: корень гильдии задан (свой `trust init`, KT от офицера своей гильдии, KA из каталога главной гильдии, связь через `link`/`accept`), корень сброшен (свой `trust reset` или KF от офицера), снят отзыв ключа (KU), запрос связи (отправлен или получен) и его подтверждение. У записи — гильдия, кто, когда и откуда. Повтор того же корня записи не создаёт, подъём и падение реле не записываются. До 300 записей в `ChillzoneDB.realms[группа][фракция].acts`; в сеть и в отчёт об ошибке журнал не уходит.
- **Персонаж автора.** `Config.AUTHOR` — «Могаю Прохожих» в группе реалмов `ForeverPvP` (`U.IsAuthor`). Сетевой власти у автора нет: всё ниже рисуется только на его экране, плюс приём отчётов.
  - «Отладка» у автора видна при любом звании.
  - «Просмотр как» (кнопка в «Настройках», строка на «Отладке», `/chillzone view [0-3]`) — вне связи, участник, Капитан, Лорд/Король, до конца сессии. Меняет только `Chat.Channels()` (каналы окна чата) и `Debug.Allowed()`. Отправку и приём по-прежнему решает настоящий `Chat.MyLevel()`.
  - Если автор в игре (виден в своём ростере или в свежей переписи), в окне отчёта есть «Отправить автору». Отчёт уходит шёпотом на «Могаю Прохожих» без реалма кусками `B1~id~i~n~текст` до 200 байт: сначала один кусок, остальные по одному после ответа автора `B2~id~1`; `B2~id~2` — отчёт собран. Не чаще раза в 10 минут, не больше 4800 байт (длиннее — обрезается). Если автор не найден, это не считается отправкой.
  - У автора принятые отчёты (до 30, от одного игрока — не больше трёх в час, одновременно собирается не больше 10) лежат в `ChillzoneDB.authorInbox`; на «Отладке» щелчок открывает отчёт в окне копирования. Остальные клиенты `B1` не разбирают, `B2` принимается только от автора. Старые версии оба типа игнорируют.

## Как это работает

На WoW: Forever сообщения аддонов в пользовательском канале **не доставляются**. Доставляются три вида сообщений:

- аддон-сообщения внутри гильдии (GUILD);
- аддон-шёпот (WHISPER). Шептать нужно на «Имя Фамилия» без реалма;
- обычный текст в канале. Аддон им не пользуется: пользовательский канал может открыть `/join` любой, кто знает название, и писать туда от имени любой гильдии.

Отсюда схема:

1. **Внутри гильдии** клиенты с аддоном раз в минуту здороваются по GUILD. Репортёр выбирается сначала среди доступных глав и офицеров, затем среди остальных подходящих участников. Внутри этой группы сохраняются выбор по имени и предпочтение согласившихся делиться зонами (`/chillzone zones on`).
2. **Репортёр** раз в ~3 минуты отправляет отчёт о гильдии **ретранслятору** шёпотом. Если ничего не изменилось, отчёт уходит не чаще раза в 10 минут.
3. **Ретранслятор** пересылает подписанный отчёт репортёрам остальных гильдий. Репортёр обновляет регистрацию каждые 15 секунд не более чем у трёх кандидатов. Сертификат должен подтверждать именно его имя и гильдию; аренда без обновления истекает за 60 секунд. При смене репортёра прежний ещё две минуты пересылает гильдии то, что ему шлют реле, и называет им преемника (`RU`), а реле передают аренду ему.
4. **Репортёр** раздаёт исходные подписанные пакеты своей гильдии по GUILD. Пересылка принимается от выбранного репортёра (при смене — и от прежнего), а подпись автора независимо проверяется каждым получателем.
5. **Строка чата** подписывается автором один раз и уходит по GUILD своей гильдии и через реле остальным. Подтверждать её у автора личным шёпотом не нужно. Повторы отбрасываются. Скрытые каналы старых версий больше не используются.

Свою гильдию каждый клиент видит только по своему ростеру. Чужие отчёты о ней игнорируются.

### Кто ретранслятор

- Подтверждённый сертификатом участник главной гильдии «Чиллзон» с аддоном; при ограничении по званию — глава, офицер или связной.
- Имена из ответов реле являются подсказками для поиска. Они не создают доверие без сертификата.
- Ручные разрешения и неподтверждённые отчёты не дают доступа в протоколе 0.4; список `RELAYS` в `Config.lua` убран.

Все клиенты одинаково упорядочивают реле: **сначала главы и офицеры главной гильдии** по свежему сертификату, затем остальные, внутри — по имени. Репортёры регистрируются у трёх доступных реле сверху списка, сообщения уходят через отвечающее реле из этой тройки, офицеры первыми. Если офицеры не отвечают, выбирается рядовой. Внутри выбранной группы сохраняется распределение по хешу гильдии и времени. Участник главной гильдии рассылает сам, только если у него зарегистрированы репортёры других гильдий; иначе отправляет реле из тройки, как все. Конфликт неподтверждённых отчётов не меняет права. Постоянный опрос выполняют репортёры; обычный читатель не опрашивает весь союз.

### Проверка по званию (сейчас выключена)

Пока звания не розданы, `TRUST_ANY_MEMBER = true`: репортёром и реле может быть любой участник. Чтобы вернуть проверку, поставьте `false` в `Chillzone/Config.lua`. Тогда:

- репортёр гильдии — только её глава, офицер или связной; если никого из них нет в игре, репортёра нет, и перепись и строки других гильдий ждут;
- реле — только глава, офицеры и связные главной гильдии;
- пересылки по GUILD по-прежнему требуют выбранного репортёра и верной подписи; настройка не отключает проверку авторства.

Связной — персонаж со званием `RELAY_RANK` (по умолчанию «Ветеран»), которое сравнивается целиком без учёта регистра и пробелов по краям. Смена звания учитывается по свежему ростеру и новому сертификату; извне отзыв узнаётся после обновления. Связной не получает офицерских прав или права выдавать сертификаты, но видит пересылаемый текст.

## Настройка

Всё, что настраивает автор, лежит в `Chillzone/Config.lua`:

```lua
C.GUILD_TOKEN = "Чиллзон"  -- подстрока в названии «своей» гильдии (без учёта регистра)
C.MAIN_GUILD = "Чиллзон"   -- главная гильдия
C.OFFICER_RANK = 1         -- значение для чистых сборщиков данных, не запасной допуск
C.RELAY_RANK = "Ветеран"   -- звание связных ("" — только глава и офицеры)
C.TRUST_ANY_MEMBER = true  -- репортёр и реле — любой участник; false — по званию
C.GUILDS = {}              -- необязательный белый список гильдий
```

**Корень доверия задаёт офицер.** В каждой гильдии один раз офицер выполняет `/chillzone trust init`: его ключ становится корнем, остальные офицеры получают корень сами. Аддон сначала 10 секунд спрашивает гильдию и не создаёт второй корень, если он уже есть. Без корня сертификаты не выдаются, и гильдия в обмене не участвует.

**Первое соединение подтверждают офицеры.** Офицер подключаемой гильдии выполняет `/chillzone link Имя Фамилия`, указывая известного офицера главной гильдии. Тот проверяет имя и гильдию вне запроса и подтверждает `/chillzone accept Имя Фамилия`. Ключи создаются автоматически и сохраняются; прописывать персонажей в коде не нужно. `/chillzone relay add` оставлен как совместимый псевдоним запроса соединения и сам по себе доверия не выдаёт.

При обновлении на 0.4 обновиться должны все стороны. Старый протокол не принимается; настройки чата сохраняются, неподтверждённое доверие сбрасывается. Подробности — в [модели безопасности](SECURITY.md).

## Ограничения

- **Реле видит текст и может сорвать доставку**, но не может изменить исходный подписанный текст или автора. Доверенными для выдачи ролей остаются подтверждённые корневые и делегированные офицерские ключи.
- **Регистрация и отправка через реле требуют сертификата.** Самозаявление о гильдии, произвольный отчёт и прямой неподписанный шёпот доступа не дают.
- **Ранги чужих гильдий для прав чата** берутся из свежих сертификатов, а не из переписи. Подписанный рядовым отчёт не делает его главой. Статистика и отображаемый состав отчёта остаются заявлением его репортёра.
- **Уровни «Офицеры» и «Главы» не секретны.** Строки всех уровней идут по GUILD всей гильдии и через реле и репортёров; любой участник может прочитать сырые аддон-сообщения. Аддон лишь не показывает эти строки тем, у кого нет ранга, и отбрасывает строки с неподтверждённым рангом.
- **Название с «Чиллзон» не создаёт доверия.** Нужны подтверждение корня гильдии и подписанный сертификат.
- Зоны видны другим гильдиям только при согласии репортёра. Отправляются только числа по зонам, без имён.
- **Офицерская строка не проходит** без действующего сертификата роли не старше 15 минут. Если издатели недоступны, членство позволяет пересылать сообщения до истечения сертификата (7 дней), но новые роли не выдаются.
- **Корневой офицер должен заходить хотя бы раз в неделю.** Делегирования остальных офицеров продлевает только он. Через 7 дней после его последнего входа выдавать сертификаты некому, и они у гильдии истекают.
- **Исключённый участник может писать от имени гильдии до 7 дней**, пока не истёк его сертификат. Раньше срока сертификаты отзываются только сбросом корня: своя гильдия делает `/chillzone trust reset` и новый `/chillzone trust init`, другие гильдии сбрасывают её корень у себя и повторяют `/chillzone link`.
- **Выход репортёра из игры.** Реле снимает его аренду сразу, по ответу сервера «игрок не найден», но гильдия выбирает нового репортёра, только когда прежний пропадёт из выборов (до трёх минут без его привета H1). Всё это время строки и перепись других гильдий в эту гильдию не приходят. Обычная смена репортёра, когда входит более подходящий, доставку не прерывает.
- **Случайность внутри игры не имеет гарантии CSPRNG.** Используется автоматическое смешивание локальных источников по подходу Olympus; это ограничение сохранено явно.

## Проверка в игре

Что нельзя проверить без живого сервера. Чек-лист:

1. Персонаж А — офицер «Чиллзон», В — глава или офицер «Чиллзон Север». А и В выполняют `/chillzone trust init` в своих гильдиях; через 10 секунд `/chillzone trust` показывает корень. Повторный `/chillzone trust init` у второго офицера той же гильдии отказывает и называет корень. В выполняет `/chillzone link Имя Фамилия А`; А после внешней проверки отвечает `/chillzone accept Имя Фамилия В`. Б — обычный участник Севера с аддоном.
2. `/chillzone status` у всех:
   - имя показано как «Имя Фамилия»;
   - группа реалмов — `ForeverPvE` или `ForeverPvP`;
   - `splitNames=true`.
3. Б и В показывают одного репортёра, с приоритетом офицера. После выхода всех офицеров подтверждённый рядовой становится репортёром и продолжает обмен. Согласие на зоны не вытесняет доступного офицера. Если входит офицер, которого выборы ставят выше, строки других гильдий, отправленные в первые две минуты после его входа, приходят Б по одному разу; через пару минут у А среди репортёров — уже он.
4. За 3–4 минуты гильдии видят друг друга во вкладке «Перепись». Король стоит наверху «Королевства». Круги на карте есть только у согласившихся гильдий.
5. `/cz1` приходит всем по одному разу. Ссылка на предмет кликабельна. `/cz2` от рядового отклоняется.
6. Чат между гильдиями идёт через реле, ссылки остаются целыми. Персонаж, который был в `ChillzoneA` со старой версии, через несколько секунд после входа из него выходит.
7. Второй участник главной гильдии Д появляется в `/chillzone relay` у Б как реле из ответа.
8. После `/reload` перепись восстанавливается по запросу у репортёра после загрузки ростера и настроек доверия. Новая установка без сохранённого доверия требует доступного офицера своей гильдии.
9. В подземелье чат блокируется. После выхода очередь уходит.
10. Персонаж Орды видит отдельную перепись.
11. `/чз привет` и `/чз1 привет` уходят в общий чат, `/чз status` — тоже текст, а `/chillzone status` выполняет команду. `/чз` без текста открывает общий канал.
12. С `TRUST_ANY_MEMBER = false`: персонаж со званием «Ветеран» в главной гильдии в `/chillzone relay` у других гильдий виден как реле; `/chillzone status` у него пишет «связной».
13. Персонаж, чьё звание не первое, но с галочкой «Офицер» в настройках гильдии, может писать в `/cz2` и виден офицером в переписи. Персонаж со званием 1 без галочки — нет. После смены галочки это видно в течение пары минут.
14. У главы или офицера `/chillzone diag` открывает «Отладку». У Б в списке реле есть А в состоянии «отвечает», а у А среди репортёров есть гильдия Б. У рядового значка вкладки нет, а `/chillzone diag` отказывает.
15. Персонаж без гильдии и персонаж из другой гильдии через `/chillzone` видят вступление. «Найти гильдии» открывает штатный `/who`; находятся гильдии своей фракции. При 50 строках следующий поиск через 10 секунд добавляет участников из диапазона уровней. Посторонний `/who` во время поиска не попадает в список адресатов.
16. Просьбу можно изменить и отправить выбранному участнику. У него она появляется над карточкой «Переписи» с именем, уровнем, классом и текстом. Офицер с правом приглашать принимает или отклоняет, рядовой направляет к офицеру, «Скрыть» ничего не отправляет. Ответ виден новичку. До отправки приглашения из другой гильдии игрок выходит самостоятельно.
17. `/chillzone nocontact on` у адресата убирает его из следующего выбора и закрывает уже открытое письмо после ответа его аддона. После `/reload` настройка сохраняется. Смена гильдии и уже вступивший новичок не допускают старое приглашение. Заявка, которой несколько часов, остаётся доступной; новые заявки не вытесняют старые при количестве больше 30.
18. После поиска, редактирования письма, отправки, принятия и отказа работают `/cast`, `/target` и штатное приглашение без ошибки taint, с мышью и в режиме геймпада. При блокировке сообщений в подземелье просьба не отправляется.
19. `/chillzone bug` у рядового и у офицера и кнопка «Отчёт об ошибке» в «Настройках»: окно открывается и не забирает клавиатуру (персонаж ходит). Щелчок по тексту или «Выделить всё», затем Ctrl+C копирует весь отчёт; вставка в блокнот — с переводами строк. Escape отпускает поле, второй — закрывает окно. Квадратов вместо букв нет. В пробах API видны флаги звания из `GuildControlGetRankFlags`, звание по `GetGuildInfo` и ростеру, `GetServerTime() - time()`. После окна работают `/cast` и `/target`.
20. Если в журнале есть ошибка: `/chillzone log` показывает её со счётчиком, на «Отладке» подсказка даёт время и стек, щелчок открывает её в окне копирования. После `/reload` записи на месте.
21. `/chillzone perf on`, пара минут обычной игры (чат, перепись, открытое окно), затем `/chillzone perf`: в отчёте метки событий, таймеров и «ed25519», без имён игроков; заметной просадки нет. После `/reload` профайлер включён. `/chillzone perf off` выключает, `/chillzone perf reset` стирает.
22. После шагов пункта 1: `/chillzone acts` у А и В показывает свой `trust init`, запрос связи и подтверждение; у второго офицера гильдии А — корни от офицера (KT). `/chillzone acts copy` открывает журнал целиком. В отчёте `/chillzone bug` записей журнала нет.
23. Автор «Могаю Прохожих» на PvP-реалме: «Отладка» видна и при звании рядового. «Просмотр как» в «Настройках» по кругу меняет каналы окна чата и значок «Отладки»; написать в недоступный по настоящему уровню канал нельзя. У игрока на PvP-реалме, у которого автор в ростере или в свежей переписи, в окне отчёта есть «Отправить автору»; через полминуты игроку приходит «автор получил отчёт», у автора — строка на «Отладке», щелчок открывает полный отчёт. Повторная отправка сразу отказывает с остатком минут. Если автор вышел, системная строка «игрок не найден» не показывается, а отправку можно повторить.

Ещё стоит проверить в игре:

- отдаёт ли `C_GuildInfo.GuildControlGetRankFlags` права званий рядовому участнику, а не только тем, кто может менять звания. Если нет — офицером считается звание с номером не больше `OFFICER_RANK` (глава и звание 1);

- проходят ли две отправки (GUILD и шёпот реле) за одну слэш-команду;
- отдаёт ли игра название звания в `GetGuildRosterInfo` и `GetGuildInfo` так, как оно написано в настройках гильдии;
- русский текст системной строки «игрок не найден»;
- совпадают ли названия зон в ростере с картой;
- работает ли карта в режиме геймпада.

Окно чата:

- окно похоже на «Гильдию и сообщества»: нет зелёных квадратов вместо текстур и значков на вкладках и в списке каналов;
- пока окно открыто, Enter ставит курсор в поле окна; после закрытия Enter снова открывает чат игры;
- `/cz`, `/cz1`–`/cz3`, `/чз`, `/чз1`–`/чз3` и `/чиллзон` с пробелом открывают нужный канал и переводят туда курсор; вставка команды вместе с текстом и ссылкой сохраняет их без отправки. Escape и исправление команды до перехода его отменяют;
- после переключения по пробелу и отправки строки из окна в обычном чате работают `/cast` и `/target` (нет taint). То же — в бою и после боя; в режиме геймпада пробел не перехватывается;
- клик по метке `[Чиллзон]` в чате игры открывает окно на нужном канале;
- строка из `/cz` видна согильдийцу без аддона в `/g` с меткой `[Чиллзон]`, а у автора и согильдийца с обновлённым Chillzone остаётся одна строка общего канала без копии во вкладке гильдии; `/cz2` и `/cz3` в `/g` не появляются;
- подсказки при наведении на ссылки в окне; Shift-клик по ссылке и по предмету в сумке вставляет её в поле;
- чат гильдии и офицерский чат работают в обе стороны и совпадают с чатом игры;
- щелчок по имени — шёпот, `/w Имя Фамилия текст` доходит;
- «Отладка»: длинные строки не наезжают на текст справа, значок вкладки не пустой;
- в режиме геймпада окно работает, Enter не перехватывается.
- «Перепись»: в карточке гильдии крупные числа, полоса классов, столбики уровней и полоски зон не наезжают друг на друга; щелчок по гильдии в списке меняет карточку.

## Разработка

```
Chillzone/          аддон (копируется в AddOns)
tests/              тесты: luajit tests/run.lua
reference/          Olympus 1.5.0 для справки (не в git)
.github/workflows/  CI и сборка релиза
.luacheckrc         настройки luacheck
```

Тесты и линтер запускаются так (luajit и luacheck на Windows ставятся через `scoop install luajit luacheck`):

```bash
luajit tests/run.lua
luacheck .
```

CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) запускает и то и другое на каждый PR и пуш в `main`.

luacheck следит за глобалами: аддон может писать только в перечисленные в `globals` из `.luacheckrc`, а читать — только Lua 5.1 и API игры из `read_globals`. Понадобилась новая функция игры — добавьте её в `read_globals`. Папка `Chillzone/libs` не проверяется.

Тесты проверяют:

- синтаксис Lua 5.1, отсутствие BOM и утечек глобалов, одинаковую версию в `Chillzone.toc` и `Config.lua`;
- регистр кириллицы, правило гильдии, имена Forever;
- кодек отчётов и чата, куски, выборы;
- приём отчётов и сроки хранения;
- работу шести клиентов в симуляторе мира (`tests/wow.lua`): перепись, реле, чат, любой участник — репортёр и реле, а с проверкой по званию — подделки пересылок от рядового, выборы репортёра по званию, связной-реле; офицер по флагу звания, а без флага — по номеру звания; смена репортёра без потери строк и без перехвата аренды; выход из старых каналов, выход реле, `/reload`, `/чз`; вкладка «Отладка»: кому видна и что на ней; приоритет главы и офицеров при выборе реле;
- окно чата: каналы по рангу, отправка из поля ввода, чат гильдии и офицеров, шёпот, метка-ссылка, непрочитанные, люди справа, привязка Enter в бою и вне боя.

Код выхода ненулевой, если хоть один тест упал.

### Выпуск версии

`main` защищена: прямой пуш отклоняется, в том числе для изменения номера версии. Ниже `X.Y.Z` — номер выпускаемой версии.

1. Создать отдельную ветку от актуальной `main`. Поднять версию в двух местах: `## Version:` в `Chillzone/Chillzone.toc` и `C.VERSION` в `Chillzone/Config.lua`. Закоммитить и открыть PR в `main`.
2. Дождаться всех трёх обязательных проверок: `Luacheck`, `Tests (lua5.1)` и `Tests (luajit)`. Слить PR.
3. Переключиться на `main` и подтянуть результат: `git switch main`, затем `git pull --ff-only origin main`. Убедиться, что обе версии равны `X.Y.Z`. Поставить тег на этот коммит: `git tag -a vX.Y.Z -m "Chillzone: версия X.Y.Z"`, затем `git push origin vX.Y.Z`. Тег ставится после слияния PR, а не на его ветку.
4. Дождаться успешного [`.github/workflows/release.yml`](../.github/workflows/release.yml). Он заново прогонит тесты и luacheck, сверит тег с версией в toc, соберёт `Chillzone-X.Y.Z.zip` и создаст черновик релиза. Если релиз уже существует, workflow приложит архив к нему.
5. Проверить приложенный ZIP: внутри одна папка `Chillzone`, состав соответствует тегу, в `Chillzone.toc` и `Config.lua` указана выпускаемая версия, исправления вошли в архив. Заполнить «Что нового» по изменениям с предыдущего релиза, указать совместимость при изменении протокола и порядок обновления. После этого опубликовать релиз и отметить его последним: `gh release edit vX.Y.Z --draft=false --latest`.

Описание можно подготовить заранее: после отправки тега создать **черновик** командой `gh release create vX.Y.Z --draft --verify-tag --title "Chillzone X.Y.Z" --notes-file notes.md`. Workflow приложит архив к этому черновику. Если черновик уже создан workflow, обновить описание через `gh release edit vX.Y.Z --notes-file notes.md`. Публикация в обоих случаях — только после проверок и появления готового ZIP.
